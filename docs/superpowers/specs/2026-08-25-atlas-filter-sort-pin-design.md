# 图鉴筛选、排序与置顶设计

## 目标

在不改变既有图鉴等级、收藏和个人库存数据格式的前提下，为图鉴增加库存条件筛选、备注来源筛选、可选排序和多图鉴置顶，并保持首次进入图鉴时不展示默认结果。

## 数据与状态

- 继续使用 `qinshi_atlas_levels_v1`、`qinshi_atlas_target_level_v1`、`qinshi_atlas_favorites_v1`、`qinshi_atlas_inventory_v1`。
- 新增 `qinshi_atlas_pins_v1`，保存已置顶图鉴 ID 数组。
- 取消收藏时同步取消该图鉴置顶。
- 新筛选和排序是页面会话状态，不写入 `localStorage`；刷新后恢复默认。
- 设置区现有备份按 `qinshi_` 前缀导出，新置顶数据自然进入备份，无需改变备份格式。

## 派生状态

每个候选图鉴基于当前等级、目标等级、升级表和个人库存派生一次状态：

- `plan`：当前等级到目标等级的升级计划。
- `soulState`：`enough`、`short`、`unset`。所需魂魄为 0 时，无论是否录入库存都视为 `enough`。
- `equipmentState`：`owned`、`missing`、`unset`。
  - 当前区间无需装备时为 `owned`。
  - 所有装备均有匹配记录且全部拥有时为 `owned`。
  - 所有装备均有匹配记录，且至少一件明确未拥有时为 `missing`。
  - 任一所需装备没有匹配记录时为 `unset`。
- `noteSources`：仅从明确未拥有装备的备注中识别来源。
- `favorite` 与 `pinned`。

装备记录继续使用 `stageKey|原始位置` 键，排序展示不改变库存键。

## 备注来源识别

支持 `禁地`、`碎片`、`碎片/禁地`、`主线`、`聚宝盆`、`楼兰`：

- 同一备注同时包含“碎片”和“禁地”时命中“碎片/禁地”，不受二者书写顺序或斜杠形式影响。
- 单独包含“碎片”或“禁地”时分别命中对应来源。
- “主线”“聚宝盆”“楼兰”独立识别，同一备注可以同时命中多个来源。
- 多选来源使用 OR 关系，命中任一已选来源即保留。
- 来源筛选仅在装备状态选择“未齐全”时生效；切换到其他装备状态时保留来源选择但暂时禁用。

## 筛选布局与行为

所有图鉴分区提供库存筛选。已收藏分区额外在首位显示图鉴类型筛选。

筛选值：

- 图鉴类型：全部类型、攻、血、内力、防。
- 魂魄：不限、已达标、未达标、未录入。
- 装备：不限、全部拥有、未齐全、未录入。
- 备注来源：多选下拉框。

电脑端四个筛选控件同一行；非已收藏分区隐藏图鉴类型后，其余三个保持同一行。手机和平板固定两行、每行两个控件，不产生横向滚动。备注来源为带复选框的自定义下拉框，收起时显示选择摘要。

首次进入图鉴不展示结果。点击分区、输入搜索、调整等级或目标、修改任意新筛选或排序后均视为主动查询并立即展示结果。清除新筛选和排序不清除既有关键词、等级范围或目标等级，也不重新隐藏已激活结果。

## 排序与分组

普通排序控件包含“排序字段”和“排序方向”：

- 默认顺序。
- 明鬼绳结：按当前等级到目标等级的剩余数量；可少到多或多到少，已完成数量为 0。
- 魂魄缺口：已达标始终排在最前，未达标按缺口升降序，未录入始终最后。
- 弟子名称：拼音 A→Z，隐藏方向控件。
- 所属图鉴名称：所属图鉴拼音 A→Z，弟子名称拼音作为次级条件，隐藏方向控件。

过滤后的结果分为三组：

1. 已置顶。
2. 已收藏但未置顶。
3. 普通图鉴。

已置顶组固定按以下条件排序，不接受用户排序：

1. 图鉴类型：攻、血、内力、防。
2. 装备状态：全部拥有、未齐全、未录入。
3. 剩余明鬼绳结少到多。
4. 弟子名称拼音 A→Z。

第二组和第三组分别应用用户排序，组之间不混排。置顶图鉴仍必须通过当前分区、关键词、等级、魂魄、装备和备注来源筛选。

## 置顶交互与视觉

- 只有已收藏图鉴显示“置顶／取消置顶”按钮。
- 已置顶图鉴在类型前显示红底白字“置顶”标签。
- 图鉴卡片外框、图鉴类型和弟子名称使用鲜红色，覆盖收藏绿色视觉。
- 收藏星号继续保持金色填充。
- 取消收藏自动取消置顶并关闭该图鉴正在编辑的库存界面。

## 核心模块边界

- `js/atlas.js`：负责派生库存状态、备注识别、库存筛选、普通排序、固定置顶排序和三组拼接；保持纯函数，无 DOM 和存储依赖。
- `js/app.js`：负责筛选状态、下拉交互、置顶存储、按钮事件和 HTML 渲染。
- `index.html`：提供紧凑筛选、排序和清除控件。
- `css/style.css`：提供桌面单行、手机平板两行、自定义多选下拉和置顶红色样式。
- `js/atlas.test.js` 与 `serve.test.js`：记录纯逻辑和页面结构契约；按项目约定由用户自行运行验证。

## 兼容性与边界

- 非收藏图鉴没有个人库存记录时为未录入，不误判为缺少。
- 旧库存记录缺少当前所需任一装备时为未录入。
- 达到目标等级的图鉴升级计划为零成本、无需装备；仍可按其他条件展示。
- 新逻辑不修改图鉴源数据和现有库存格式，不更新 PWA，不推送 GitHub。
