# 单只机关兽库存优先问题

历史阶段记录：本阶段修复未单独发布，后续用户补充了可拆解/升阶规则，已纳入可转换库存模型一并实施；最终规则见2026-11-18-machine-beast-convertible-stock-design.md。

## 复现与根因

用户确认范围为单只机关兽培养，不是目标流派两套方案。

机关炎傀当前研发度0，目标10级（317,700研发度），0阶库存20只（每只48,000），新增范围0–7阶，使用库存开启。旧UI明确传入preferOwnedOnTie，但算法仍以总投入只数为第一目标：选择2只0阶库存＋新增3只7阶（总研发321,756），留下能覆盖整个目标的大量库存。

全部使用7只0阶库存即可达到336,000研发度，无需新增本体。旧算法按5只总投入停止，并把库存组合上限限制在全新高阶解附近，因此不能只调整最终比较器。

## 修订

- 单只UI新增prioritizeOwnedInventory选项，使用库存开启时按新增折算投入最少→总投入最少→溢出→碎片缺口、贡献、元宝、神图、机铸及稳定顺序比较。
- 按新增数外循环，完整比较对应的有限库存组合，之后才停止；库存候选上限采用不冗余子集的安全数量界限，不再按全新高阶解截断。
- 保留旧API默认优先总投入的兼容路径；关闭使用库存时恢复原行为。
- 库存按指定阶数上限使用，不强制耗尽；改造、高阶折算、Worker和主线程回退仍沿用既有机制。
- 目标流派计算文件、游戏数值、真实账号及存储格式未修改。
