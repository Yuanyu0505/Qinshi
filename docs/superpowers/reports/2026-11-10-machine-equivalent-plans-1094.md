# 全部同等最优组合与补充布局调整（1.0.94）

## 为什么此前只显示一套

原求解器按实质指标排序后，继续用稳定键选定唯一代表，并在中间状态和单兽材料状态中丢弃其他完全相同指标的路径。前次独立枚举虽然说明了两套同价方案，网站仍按这个旧返回契约只展示一套。本次改变的是同等解保留与展示契约，不改变价格、资料、目标等级或实质排序优先级。

同等条件：改造本体折算投入、已计价元宝、新增效果节点、研发度溢出、神图总消耗全部相同。稳定键只决定主展示顺序，不再排除其余同等组合。

## 实现

- 跨兽DP遇到全部实质指标相等时，合并完整前驱路径；严格更优/更劣仍按原规则处理，新增等级仍必须恰好达到目标。
- 中间路径用共享DAG保存，结果用平面节点索引序列化，不把共享前驱展开成指数JSON。
- 对最优路径中的单兽，按完整允许材料类型反向重建所有满足相同研发度、神图、改造和本体费用的数量向量。包含原稳定键过滤掉的同兽不同材料配法、碎片足够或零价导致的已有/新增同价选择；库存上限和材料开关依旧生效。
- 固定材料类型顺序枚举数量，避免把同一数量向量的不同投入顺序、库存二进制拆分历史当作不同方案。
- 用BigInt精确计数，传输/历史状态中使用十进制字符串；按序号解码分页，不设20套等静默截断。单次页面调用最多50套只是批大小限制，网站按每批10套持续加载，可查看至全部。
- 主方案保持原返回字段，新增`equivalents`压缩路径。分页解码后重新汇总实际材料、碎片、贡献、机关破片、费用及最终效果，并核对所有实质指标和目标等级，防止复制主方案数字冒充另一组合。
- 其他组合直接嵌入原“培养材料”内，逐套展开；不增加顶层方案面板。区分主展示最终效果和其他组合最终效果，明确不同组合互相替代、不要累计投入。
- 分页只读既有图，不重新求解、不消耗库存、不保存到账号。已展开状态和加载批数只放在原`presentation`。
- 新模块同时接入Node、浏览器懒加载、Worker、离线缓存和GitHub Pages产物；Worker消息和取消协议不变。

主要文件：`js/machine-beast-equivalents.js`、`js/machine-beast-school-planner.js`、`js/machine-beasts-ui.js`。本次明确涉及等价解路径保留，超出了上一轮纯UI范围，但没有调整业务排序、费用公式或游戏资料。

## 同时完成的两项补充要求

- 所有当前UI中的“新增解锁节点／新增效果解锁节点数”统一显示为“新增效果节点”；数量紧随标签，三项摘要在同一行。研发度、增加、溢出也保持同一行并缩小间距；仍使用共享行轨道对齐卡片。超长数值局部横向滚动，不截断、不制造整页横向溢出。
- 蓝色和紫色分别保留独立研发度表格并排展示。蓝色放左侧，对齐橙色矩阵前两列；紫色放同一行后侧，共用橙色七列网格基准及表头/行高。窄屏保留两张独立表格，以局部滚动承载，资料数值未改。

## 检查状态与用户验收

遵照当前AGENTS，**本轮未主动运行测试、lint、浏览器渲染或手动验收**。不能声称运行正确性、性能或视觉测试已经通过。

新增供用户执行的检查包括：

- 多只兽完全同价，稳定键只选主展示，其余全部保留。
- 同兽不同阶数/改造材料完全同指标。
- 碎片覆盖或零价时，已有和新增材料的同价向量。
- 不同费用、溢出、神图或超库存的组合不能混入。
- 小数单价和共享神图库存抵扣；严格目标97→135、两套647,052元宝/6节点组合及未培养兽最终效果复位。
- 120套组合连续分页无遗漏重复；超过安全整数的组合总数使用字符串精确保存；主方案处于末尾时没有空的加载页。
- 网站只在培养材料内显示其他组合、不额外增加主方案面板、不写账号；三项摘要/研发度同一行，蓝紫并排且蓝色列与橙色一致。
