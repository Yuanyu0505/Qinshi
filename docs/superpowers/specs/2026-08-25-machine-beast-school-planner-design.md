# 机关兽流派目标阶数计算设计

## 背景与目标

现有“机关兽 → 方案计算”以单只机关兽为计算对象。本次在保留既有单只计算的基础上，新增“目标流派阶数”计算，使玩家能够根据霸道机关术或非攻机关术下全部机关兽的个人进度、库存和可选培养范围，计算达到目标流派阶数的全局最优投入方案。

目标流派阶数与累计觉醒等级固定映射如下：

| 流派阶数 | 累计觉醒等级 |
| --- | ---: |
| 1阶 | 45 |
| 2阶 | 90 |
| 3阶 | 135 |
| 4阶 | 180 |
| 5阶 | 225 |

## 功能范围

### 计算子页面

“机关兽 → 方案计算”拆分为两个子页面：

1. 单只机关兽
2. 目标流派阶数

单只机关兽保留当前计算能力，同时补充可控的已有库存使用功能。目标流派阶数则跨同一流派的全部机关兽进行全局优化。

### 单只机关兽库存控制

- 新增“使用已有库存”开关，默认开启。
- 默认勾选该机关兽的全部已有库存。
- 库存按“机关兽、阶数、改造状态”形成独立条目。
- 每个条目可取消使用，也可设置本次最多使用数量；默认上限为当前库存总数。
- 取消使用或降低数量上限只影响本次计算，不修改已保存个人进度。

## 目标流派阶数计算输入

### 流派与目标

- 选择霸道机关术或非攻机关术。
- 选择目标1–5阶，并自动换算为45／90／135／180／225累计觉醒等级。
- 默认目标为当前已达成阶数的下一阶。
- 当前已达到5阶时，默认保持5阶并显示“最高阶已达成”。
- 若玩家手动选择的目标已经达成，直接展示已达成状态，不推荐额外投入。

### 个人进度起点

- 默认读取所选流派下全部机关兽已保存的当前研发等级、累计研发度、库存和机关兽碎片。
- 计算页允许临时调整上述数据。
- 临时调整仅作用于本次计算，不自动覆盖个人进度。
- 当前流派累计觉醒等级等于该流派所有机关兽当前研发等级之和。

### 参与范围

- 默认该流派全部机关兽参与计算。
- 玩家可取消任意机关兽参与后续培养。
- 被取消的机关兽已有研发等级仍计入当前流派累计觉醒等级，但不能继续使用库存或新增投入。
- 库存只能投入同名机关兽，不能跨机关兽使用。

### 已有库存

- “使用已有库存”默认开启。
- 默认选中全部已有库存条目。
- 每个“机关兽、阶数、改造状态”条目可独立取消或设置最大可用数量。
- 玩家明确选中的8–10阶或改造库存可以直接使用，不受“新增8–10阶方案”或“新增改造方案”开关限制。

### 新增候选

- 默认只允许新增0改、0–7阶机关兽。
- 玩家可独立开启新增8–10阶候选。
- 玩家可独立开启新增改造候选。
- 8阶、9阶、10阶分别按2、4、8只7阶本体折算投入机关兽数量。

## 两套推荐方案

### 自由等级方案

允许机关兽培养到任意整数研发等级，不刻意停留在10、15、20、25级效果档位。

### 效果档位方案

同样允许培养到任意整数研发等级，但在投入机关兽总只数最少的前提下，尽量让更多机关兽最终停留在10、15、20、25级效果档位。

若两套方案的机关兽培养终点、库存消耗和新增投入完全相同，则合并展示，并标注“同时满足自由等级与效果档位优化”。

## 优化规则

所有候选方案必须先达到目标流派累计觉醒等级，再按以下顺序比较：

1. 投入研发的机关兽折算总只数最少。
2. 折算总只数相同时，优先使用玩家勾选的已有库存，减少新增机关兽数量。
3. 效果档位方案继续比较处于10、15、20、25级的机关兽数量，数量更多者优先。
4. 新增研发度溢出更少者优先。
5. 觉醒神图、机关破片、机关兽碎片、贡献和元宝的综合消耗更少者优先。
6. 其余条件相同时，使用稳定排序保证相同输入始终得到相同结果。

已有库存也计入“投入研发的机关兽折算总只数”。高阶机关兽按其实际合成消耗折算，而不是简单按一只计数。

## 计算架构

采用分层动态规划，不使用逐只贪心或全量暴力穷举。

### 第一层：单只机关兽候选生成

对每只允许参与的机关兽，基于以下约束生成可行的培养候选：

- 当前研发等级和累计研发度；
- 该机关兽研发上限；
- 可用库存条目及数量上限；
- 是否允许新增8–10阶；
- 是否允许新增改造机关兽；
- 同名机关兽限制；
- 各阶、各改造状态的研发度与资源消耗。

候选覆盖当前等级至研发上限之间的任意整数等级，并保留达到相同等级时在优化规则下不被支配的方案。

### 第二层：流派组合优化

将每只机关兽的候选按累计新增等级组合，形成达到目标流派累计等级的全局方案。动态规划状态至少包含：

- 已处理机关兽范围；
- 累计新增研发等级；
- 折算投入总只数；
- 已有库存使用量与新增量；
- 效果档位命中数；
- 研发度溢出；
- 资源消耗汇总。

计算自由等级方案时不比较效果档位命中数；计算效果档位方案时在既定优先级位置比较该值。每个状态只保留不被更优方案支配的候选，控制浏览器端计算规模。

### 计算安全边界

- 不修改数据源。
- 不自动扣除库存、碎片、贡献或元宝。
- 不自动保存临时输入。
- 不自动应用计算结果到个人进度。
- 计算结果只作为规划参考。

## 结果展示

### 顶部汇总

每套方案展示：

- 流派名称；
- 当前累计觉醒等级；
- 目标阶数和目标累计觉醒等级；
- 计算前还差等级；
- 推荐后累计等级；
- 投入机关兽折算总只数；
- 使用已有库存数量；
- 新增机关兽数量；
- 研发度溢出；
- 觉醒神图、机关破片消耗；
- 机关兽碎片缺口；
- 贡献与元宝合计。

### 机关兽明细

只展示发生变化的机关兽，并列出：

- 当前等级及当前累计研发度；
- 推荐终点等级及终点累计研发度；
- 增加的研发等级；
- 使用的已有库存明细；
- 新增投入明细；
- 研发度增长与溢出；
- 本体、机关兽碎片、贡献和元宝缺口。

没有发生变化的机关兽不占用结果主体空间，可在汇总说明中标记其等级已计入流派起点。

## 交互与布局

- 计算结果在点击计算后优先展示于输入区域上方，与兵法计算区现有交互保持一致。
- 已有库存按机关兽分组，条目支持勾选和最大使用数量输入。
- 参与机关兽列表同时展示当前等级、研发上限和是否参与。
- 桌面端采用紧凑多列布局。
- 手机和平板端改为单列或双列卡片，避免依赖横向滚动；本次不更新PWA，除非用户另行要求。
- 两套方案使用清晰标签区分；相同方案合并后只展示一份。

## 数据兼容

- 继续使用现有个人进度存储结构，不迁移或删除既有数据。
- 新增的临时计算设置不写入个人进度。
- 如需保存“是否使用库存、库存数量上限、参与机关兽”等界面偏好，使用独立可选字段，并为旧数据提供默认值。
- 原有单只机关兽计算调用保持兼容；公共候选生成逻辑可以复用，但不改变既有数据含义。

## 验收要点

1. 单只机关兽计算可以整体关闭已有库存，也可以逐项限制库存数量。
2. 流派目标阶数正确映射为45／90／135／180／225。
3. 默认读取个人进度，但临时编辑和计算不会覆盖个人进度。
4. 取消参与的机关兽仍贡献现有等级，但不会获得新增投入。
5. 8–10阶按2／4／8只7阶本体计入总只数。
6. 已勾选高阶或改造库存不受新增候选开关限制。
7. 自由等级方案可停在任意整数等级。
8. 效果档位方案在总投入只数相同的前提下优先10／15／20／25级。
9. 两套结果相同时合并展示。
10. 汇总资源等于各机关兽明细资源之和。
11. 目标已达成时不产生额外投入。
12. 旧的机关兽个人进度和单只计算数据不丢失。
