# 铭文交互性能优化设计

## 目标

在不改变铭文数据、筛选规则、结果顺序、个人进度联动和现有视觉信息的前提下，消除“个人进度 / 查询筛选 / 资料图表”切换及铭文内部输入时的明显卡顿。

## 已确认根因

- 铭文初始化时会提前渲染三个子页面，包括两个隐藏页面。
- 未筛选的查询结果一次创建 242 张卡片、1,061 个槽位和 8,560 个属性标签，整页约 2.9 万个 DOM 节点。
- 桌面、平板、手机三种尺寸切换到查询页均耗时约 340–390ms。
- 搜索框每次输入都会同步重建完整结果；下拉框同时监听 `input` 和 `change`，一次操作可能重复渲染。
- 查询卡片中重复使用的绘制效果会放大大列表的布局和绘制开销。

## 方案

1. 增加独立、可测试的铭文渲染协调器。个人进度首次加载时正常渲染；查询页和资料页仅在首次打开时渲染。
2. 已渲染且未失效的页面在来回切换时直接复用 DOM。保存或删除个人进度后，立即更新当前个人进度页，仅将隐藏的查询页标记为待更新。
3. 搜索框采用 120ms 合并刷新，连续输入只执行最后一次查询；品质、天位、盾位下拉框仅监听 `change`，每次选择只刷新一次。
4. 查询卡片和进度卡片启用浏览器原生视口外延迟布局与绘制，避免显示查询页时计算屏幕外的数百张卡片。
5. 保留星形 4px 描边，使用较轻的文字阴影代替逐个星形滤镜。

## 保持不变

- 不分页，不截断查询结果，不改变结果数量。
- 不改变铭文品质、主属性、副属性、极致属性及个人进度的数据结构。
- 不改变查询匹配条件、保存结果优先级、品质排序和姓名排序。
- 不改变电脑、平板、手机端已有的信息结构和操作入口。

## 验收重点

- 首次加载不创建隐藏的查询与资料内容。
- 首次进入各页面时按需渲染；再次切换不重复渲染。
- 隐藏查询页失效后，只有再次打开时才更新。
- 连续搜索输入合并为一次刷新，下拉框每次选择只刷新一次。
- 三端切换、搜索、保存、删除和资料表显示保持可用。

## 同批响应式布局修正

- 装备属性副属性筛选按钮固定在一行内，通过缩小间距、内边距和字号适配宽度，不使用横向滚动。手机端将“敌方减攻 / 敌方减防 / 敌方减血”显示为“减攻 / 减防 / 减血”，完整名称保留在无障碍名称与提示中。
- 典籍品质列中的“进阶详情”固定单行显示。
- 锻造材料总览在电脑和平板端使用等比例紧凑列；手机端转为每个装备类别一张两列阶段网格卡，三端均取消横向滑动，合计按材料分行突出。
