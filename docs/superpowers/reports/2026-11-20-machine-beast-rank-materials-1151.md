# 机关兽 1.1.51｜仅0阶与库存加工

以 1.1.50 的 `a18968d` 为基线，实施修订稿中已有证据的规则。存档、资料数值、价格、正式择优指标及优先级不变。

## 本轮已执行

- “仅0阶”不再生成依赖未核实返料的升阶方案。0–10 阶原形可直投；同名库存可降阶；8/9/10 阶可拆作 2/4/8 个 7 阶本体。高阶重组由独立开关控制，只有原生或拆出的 7 阶库存足额才可重组，不能拿新增 0 阶凑数。
- 求解和同等方案分页构建都按高阶到低阶逐级核对库存容量。对每个 1–7 阶门槛，需达到该门槛的投入本体数不得超过可合法提供该阶及以上本体的库存；高阶原形有单独原始库存上限，不与拆解重复。从高阶需求开始匹配能覆盖这一组嵌套约束，无需模拟返料或把无法重建的方案留给 UI 处理。
- “0–7阶”保留已确认的自由加工口径和现有高阶开关。改造神核的同名归属及独立结算不变，不用于补足升阶材料。
- 展示优先级为品质、阶数、改造档位依次降序。单兽、流派、同等方案、加工及余量共用排序；不更改用于求解与分页的指标顺序。
- 机关岳獠截图配置（2–7 阶各 1 只，0 级升 25 级）：“仅0阶”在已证实范围内需新增 17 只 0 阶、总研发度 1136838；切换“0–7阶”原方案仍新增 10 只。

## 数据缺口：返料后再升阶暂未启用

`data/machine-beasts.js` 的 `breakthroughGuide.stages` 列出逐阶成品消耗，不含下列经过确认的游戏规则：

1. 各次降阶实际返还的材料名称、数量以及返的是成品、图纸、原材料还是混合。
2. 7→6 的返料能否用于另一只同名兽的 5→6、是否能跨阶段、跨品质或跨名称，以及适用的限制。
3. 8–10 阶拆成 7 阶本体之外，是否另退材料；若有，实际明细是什么。

因此 7 阶×1、5 阶×1 不会被自动算作 6 阶×2。这个组合不是已证伪，而是材料可行性未核实；当前结果仅在无需返料升阶的候选中择优。等待游戏实际降阶返还清单与可转用规则后，再加入逐材料账本、跨个体供受体和多供体验收。
