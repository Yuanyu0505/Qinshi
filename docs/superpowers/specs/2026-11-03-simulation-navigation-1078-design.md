# 1.0.78 模拟连续合成、机师布局与切换性能

用户要求直接修改、完整测试一遍无误后合并master并更新PWA/推送。沿用现有原生JS/CSS和概率模型，不反复确认设计。

## 模拟

- 默认勾选自动加入虚拟背包，按账号保存；开启时不显示单独入包按钮。关闭仅影响后续新结果，不删除已入包的结果；可手动保存未入包结果。
- 重复当前阶段直接完成一次新合成，旧结果保留、新结果另入包；重新模拟仍替换当前结果，不累计产物。背包投料严格扣量；不足时整次操作不写入、不凭空补料。
- 结果产生后可直接编辑或清空材料、使用背包准备下一批，不再被pending锁死。开启自动入包时保存旧结果，再解除其待处理状态。继续使用旧接口的低层roll/repeat语义以兼容旧档/既有调用；页面采用明确的连续合成动作。
- 关闭自动入包后，手动入包与下一阶段携带产物仍可用；单纯换材料或重复新一批不强制把旧结果入包，历史记录仍保留。
- 撤销、重抽、跨账号、存储写入失败均保留现有事务性保护。

## 机师

一级分类→二级类别/阶数→搜索→三行统一机师说明→结果。类别按钮紧密相邻，沿用全站样式；说明不再拆散在按钮下面。正文用明确标题和舒适行距改善阅读，不改效果数据。

## 性能调查及取舍

已测CPU4x浏览器：首次铭文查询同步125–211ms，约57万字符HTML；合成两个子页反复切换每次13次HTML写入，含隐藏页。优先修复这两个明确热点，保留原筛选结果与账号安全通知。首次查询采用可取消小批渲染，隐藏/新筛选取消旧任务，返回补全；合成页不重建无变化的现场，只刷新实际打开页，共享数据变动时失效。

同时检查全站导航、禁地、秘境与收藏事件；只实施有证据、可回归验证的改动。不承诺消除网络/设备负载等所有偶发延迟，不以跳过数据刷新或只读保护换取性能。

## 验证

先RED/GREEN核心事务、结果后换料、自动入包开关和库存不足回滚；浏览器覆盖连续点击、重抽、切换重载、账号隔离及390/768/1280布局。现有全量单元与39文件浏览器测试完整一遍通过后发布1.0.78。测试只用隔离账号。
