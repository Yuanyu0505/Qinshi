# 手机、平板适配与 PWA 1.0.37 发布设计

## 1. 目标与发布边界

本次以远端 `origin/main` 的 PWA `1.0.36`（提交 `ce22009`）为发布基线，覆盖该提交之后至 `505b1ca` 的全部本地业务改动。适配重点是图鉴收藏排序、禁地用途与跨分区跳转、禁地机关兽奖励拆分、禁地性能与视觉分组、历史状态恢复，以及奖励详情批量展开。

不提交主目录现有的说明文档、服务脚本、源工作簿、截图、图片或临时测试文件；业务改动继续在独立 worktree 中完成。

## 2. 响应式目标

- 手机竖屏覆盖 320px、390px；手机横屏覆盖不高于 500px 的 768px～932px 视口。
- 平板覆盖 768px、900px、1024px。
- 页面根节点不得产生非预期横向溢出；资料宽表若保留局部横向滑动，必须限制在明确的滚动容器内。
- 手机和平板上的主要按钮、输入框和可点击道具子操作目标不低于 44px。
- 禁地默认“当前＋下一期”、完整预测表、搜索结果和用途筛选结果使用同一套响应式规则。

## 3. 禁地布局

桌面保持现有紧凑布局。平板将类型筛选独占一行，`只看已勾选`、完整预测和奖励批量展开形成稳定的两列操作区；用途筛选保持三列。手机将所有全局操作纵向铺满，用途筛选改为两列，避免标签压缩。

禁地奖励标签内部的勾选、名称跳转和用途设置均获得独立 44px 触控区域。窄屏下已勾选标签改用网格排列：勾选按钮位于左侧，名称占剩余宽度，用途标记及设置按钮置于下一行；长名称允许换行但不会挤出卡片。

用途编辑器在手机端继续使用底部面板，在平板端使用居中弹窗；两种形态都限制在可视区域内，并保证保存、取消、取消勾选按钮可触达。

## 4. 自动化与浏览器验收

先扩展 Playwright 响应式测试，使其覆盖全部主要分区的 390px、768px、1024px 页面宽度，并对禁地默认视图、完整预测表、用途编辑器、单卡与批量展开、触控尺寸及横向溢出建立断言。新增断言必须先在现状上暴露问题，再修改样式。

同时修复因统一装备族跳转后语义变化而失效的两个既有 Playwright 测试：个人进度搜索允许同装备族的“直接持有＋材料需求”共同出现；装备属性跳转使用统一操作菜单，不再依赖旧的直接锻造按钮。

最终验证包括：Node 单元测试、Playwright 手机/平板布局与交互测试、关键页面截图人工检查、静态站点资源清单检查。Python 数据生成测试中的章节掉落数量基线差异单独记录，不修改或上传源工作簿，也不以篡改期望值掩盖来源数据缺口。

## 5. PWA 发布

验收完成后将 `service-worker.js`、`js/pwa.js` 和 `index.html` 的版本统一升级到 `1.0.37`，确认 `manifest.webmanifest` 的分区说明以及本轮新增或修改的运行资源均在预缓存和 GitHub Pages 发布清单中。发布提交快进合并到本地 `master`，再推送为远端 `main`，并检查线上 Service Worker 已返回 `1.0.37`。
