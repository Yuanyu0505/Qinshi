## 2. 推荐恢复方法：恢复到新目录，不覆盖当前项目

先把备份文件夹复制到另一个磁盘或备份位置。单一磁盘上的标签和 bundle 无法抵御磁盘损坏。

PowerShell 中运行（目标目录必须是尚不存在的新目录）：

```powershell
git clone --branch checkpoint/qin-1.1.52-20261120 "C:/Users/pghyl/Desktop/deepseek/outputs/checkpoint-Qin-1.1.52-20261120/Qin-1.1.52-checkpoint.bundle" "C:/Users/pghyl/Desktop/Qin-restore-1.1.52"
git -C "C:/Users/pghyl/Desktop/Qin-restore-1.1.52" switch -c restore/qin-1.1.52
```

按标签 clone 后短暂处于 detached HEAD 是正常现象，第二条命令创建可继续开发的分支。离线 clone 的 origin 指向 bundle；将来确需推送时再由维护者显式设置 GitHub remote，不自动推送。

若原仓库仍正常，也可只在原仓库建立检查点分支：

```powershell
git -C "C:/Users/pghyl/Desktop/deepseek" branch restore/qin-1.1.52 checkpoint/qin-1.1.52-20261120
```

这只建分支，不切换、不覆盖当前修改。不要直接使用 `reset --hard` 或强制推送“恢复”，以免丢失后续工作。

恢复本地补充文件时，先比较现有文件与备份，确认后在恢复目录中复制 `working-files/` 下的同名相对路径。不要将整个 working-files 当成项目根目录，也不要将真实个人资料提交上传。

## 4. 当前关键规则及未解决边界

### 机关兽

- 所有方案显示按品质（橙五优先）、阶数、改造档位降序；显示顺序不是求解优先级。
- “仅0阶”不允许免费升库存。仅生成原形直投、降阶、已确认高阶拆解，以及独立开关允许且有真实 7 阶本体供给的高阶重组。新增本体只能 0 阶。
- “0–7阶”保留自由加工口径；8/9/10 阶折算 2/4/8 本体；神核单独按同名精确核算。
- **降阶返料后再升阶仍未完整实现**：缺少已核实的返还种类、数量、形态和转用限制。7阶×1＋5阶×1是否可成为6阶×2不能靠阶数加减断言。结果明确仅在无需返料升阶的候选中择优，不是假称完整材料规则的全局最优。
- 详见 `docs/superpowers/reports/2026-11-20-machine-beast-rank-materials-1151.md`。

### 木人巷

- 修正小棋盘覆盖漏解、禁用道具仍推荐、失败写入内存假成功和 Worker 主线程降级卡顿风险。
- 单层覆盖有精确搜索；跨层不能证明的结果会标为未知或可达区间，不能将当前候选失败当作无解。
- 炸药等概率抽样规则是未核实的模型假设；期望／保守估计不保证通关。不要据 UI 重排擅改游戏数值。
- 读取坏档时禁止将空白预览覆盖原数据；只有确认清空才允许重建。
- 1.1.52 仅把未击破棋盘格与建议棋盘换成用户 PNG，保留勾选和操作；未修改计算逻辑。
- 详见 `docs/superpowers/reports/2026-11-20-wooden-man-1150.md`。
