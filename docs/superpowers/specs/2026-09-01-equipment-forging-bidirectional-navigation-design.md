# 装备属性与橙装锻造双向跳转设计

## 目标

在既有“装备属性装备名 → 橙装锻造查询”的单向跳转基础上，增加一次性返回会话和橙装锻造结果名反向跳转，同时严格保留两个分区原有搜索、筛选和计算规则。

## 范围

- 装备属性搜索或筛选结果中的可锻造装备名继续支持正向跳转。
- 橙装锻造“查询”页中，“作为主锻造装备”和“作为素材装备”生成的主装备结果名支持反向跳转。
- 橙装锻造个人进度、材料名称、材料总览不增加跳转。
- 手机、平板和桌面使用同一状态逻辑，并分别提供合适的触摸和键盘焦点区域。

## 正向跳转与一次性返回会话

从装备属性结果点击装备名时，创建内存返回会话：

- `sourceItemId`：来源装备属性条目 ID；
- `forgeName`：本次正向解析出的精确锻造名称；
- `equipmentView`：搜索词、分类、收藏筛选、主属性、副属性、排序、主属性显示和装备对比状态；
- `scrollY`：跳转前页面纵向滚动位置；
- `valid`：会话是否仍可返回。

随后进入“橙装锻造 → 查询 → 作为主锻造装备”，写入精确锻造名称并立即渲染。

滚动橙装锻造页面不会使会话失效。以下用户动作会立即使会话失效：

- 修改锻造搜索词；
- 切换“作为主锻造装备／作为素材装备”；
- 切换“查询／个人进度”；
- 点击其他分区；
- 点击与 `forgeName` 不同的锻造结果装备。

会话有效且点击结果名与 `forgeName` 完全相同时，恢复 `equipmentView`，进入装备属性分区，重新渲染原结果，并在渲染完成后恢复 `scrollY`。返回消费本次会话；再次正向点击会创建新会话。

## 反向跳转

不存在有效同名返回会话时，点击锻造结果装备名执行反向解析：

1. 在所有能够正向解析到该锻造名称的装备属性条目中，优先选名称以“神兵”开头的条目。
2. 特例：锻造名称“鬼谷子”和“神兵鬼谷子”均反向解析为“神兵鬼谷子”。
3. 没有神兵对应项时，选择精确对应的普通装备属性条目。
4. 装备属性数据中完全没有对应条目时，锻造结果名保持普通文字。

反向跳转进入装备属性分区后：

- 搜索框替换为解析后的完整装备名；
- 清除分类、收藏筛选、主属性、副属性和排序条件；
- 保留收藏数据、装备对比状态和“展示主属性”开关；
- `activated` 设为 `true`，继续通过现有 `Q.queryItems` 产生结果，不改变查询语义。

有效返回会话中点击不同锻造装备时，先取消原会话，再对新装备执行上述普通反向跳转。

## 分区导航控制

将当前仅存在于 `bindTabs()` 闭包内的分区切换逻辑提升为可由界面事件和程序化跳转共同调用的控制器。接口区分两类来源：

- 用户直接点击导航：保持现有普通进入装备属性时重置筛选的行为，并按规则取消返回会话；
- 装备／锻造名称触发的程序化导航：允许保留或恢复装备视图，不调用 `resetEquipmentView()`。

不引入 URL 路由或 History API，不修改浏览器返回键。返回会话不写入 `localStorage`；刷新、关闭网页或重启 PWA 后自然失效。

## 映射模块

扩展 `js/equipment-forging.js`：

- 保留 `resolveForgeTarget(name, forgingItems)` 和 `buildForgeNavigation(...)`；
- 新增 `resolveEquipmentTarget(forgeName, equipmentItems, forgingItems)`，返回装备属性条目或 `null`；
- 新增返回会话构造与精确匹配纯函数，供界面层使用并单元测试；
- 反向解析复用正向解析结果，避免维护两份容易漂移的完整映射表，仅保留“鬼谷子”显式特例。

## UI 与可访问性

可反向解析的锻造主装备名渲染为按钮，保留现有品质色块外观。有效同名返回会话下，按钮提示“返回装备属性筛选结果”；普通反向跳转提示“查看对应装备属性”。按钮具备键盘焦点轮廓，手机和平板触摸高度不小于 44px。

## 错误与边界处理

- 正反向解析失败时不生成可点击按钮，不产生空结果跳转。
- 返回快照字段均复制数组和嵌套对比状态，避免跳转后被引用修改。
- 恢复滚动位置在装备结果重新渲染后的动画帧执行，并受页面最大滚动范围自然约束。
- 程序化写入锻造查询时不触发用户输入失效逻辑；只有真实事件取消会话。

## 验证与发布

- 单元测试覆盖正反向映射、神兵优先、鬼谷子、普通回退、无映射和会话精确匹配。
- 页面集成测试覆盖两种锻造查询模式的按钮、状态保存／恢复、失效入口和响应式样式。
- 回归现有装备查询、收藏、对比、锻造查询、个人进度和 PWA 资源测试。
- 全量测试通过后将 PWA 从 `1.0.21` 升级为 `1.0.22`，合并本地 `master`，推送 GitHub `main` 并核对 Pages 部署资源。
