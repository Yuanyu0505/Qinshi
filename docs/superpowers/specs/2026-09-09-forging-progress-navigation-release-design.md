# 橙装锻造个人进度交互与全端发布设计

## 1. 目标

让橙装锻造“个人进度”中的装备名称、锻造阶段和材料命中展示与“查询”分区保持一致，并对 PWA 1.0.35 发布后至本次完成的全部改动执行手机、平板专项检查，最后发布新的 PWA 版本。

## 2. 个人进度装备操作

- “弟子直接持有”和“尚未完成的锻造材料需求”中的装备名称都使用统一物品菜单，来源统一视为 `forging`。
- 菜单固定包含：前往个人进度查询、前往图鉴分区查询、前往关卡掉落分区查询、前往装备属性分区查询、前往禁地分区查询、前往逐鹿分区查询。
- 阶段表中的真实装备材料同样可打开该菜单；横杠、进化石等非装备材料保持不可点击。
- 跳转继续复用现有普通版映射、鬼谷子双键、共享装备族查询和多级返回栈；无目标资料时正常显示“未找到”。

## 3. 阶段编辑

- 两类搜索结果中的阶段按钮都可直接修改对应弟子装备的实际锻造进度。
- 点击任意阶段或“全部完成”后保存本地进度，并立即重新计算当前搜索结果。
- 搜索结果只提供阶段编辑，不开放品质切换和移除装备，避免误操作扩大。

## 4. 材料需求说明与命中高亮

- 每个材料需求结果使用一个连续语句：`弟子名 · 实际持有装备名的锻造需要该装备：阶段 装备名`。
- 弟子与实际持有装备名为一个强调片段；阶段与命中装备名为另一个强调片段。
- 多个命中阶段使用分号分隔；桌面优先单行，手机允许句内自然换行，但不得拆成两个独立信息区或造成横向滚动。
- 命中的阶段按钮使用边框同色的实心底色和白色文字。
- 剩余材料表中命中的整个阶段行使用可辨识的背景、边框或内描边高亮，且不得影响装备品质色和可点击状态。

## 5. 手机与平板专项适配

- 审查范围为 PWA 1.0.35 发布提交之后至本次方案完成的全部产品代码改动。
- 重点检查：橙装锻造三种查询模式、个人进度两类结果、统一物品菜单、返回提示、逐鹿、关卡掉落、装备属性和所有新增跳转落点。
- 手机视口使用 390×844；平板至少覆盖 768×1024 和 1024×768；桌面使用 1440×900 作为回归基准。
- 检查横向溢出、文字可读性、44px 触控目标、菜单不越界、焦点恢复、自然换行、固定/悬浮控件遮挡和横竖屏布局。
- 对发现的问题仅做响应式样式或布局修复，不改变已确认业务规则和资料数据。

## 6. 弟子顺序调整

- 在个人进度分页栏的“下一页”旁提供“调整顺序”入口。
- 进入调整模式后，在分页栏下方展开全部已保存弟子；第一次点击选中弟子 A，第二次点击弟子 B，交换两者位置并清除选择，可连续执行多次交换。
- 调整过程只操作临时顺序，不立即写入本地存储；“保存顺序”一次性提交并自动关闭界面，“取消调整”放弃全部未保存交换。
- 保存后当前弟子页按照弟子 ID 跟随到新的页码，避免排序后突然显示另一名弟子；总览页保持总览页。
- 交换的是完整弟子记录，名称、装备和进度随记录整体移动。
- 手机使用单列按钮，平板与桌面使用自适应多列；所有操作按钮保持至少 44px 触控高度且不产生横向滚动。

## 7. PWA 发布

- 将显示版本、运行时版本和 Service Worker 缓存版本从 `1.0.35` 同步提升到 `1.0.36`。
- 确认本次新增或修改的运行时资源在 Service Worker 预缓存及 GitHub Pages 发布清单中可用。
- 更新发布说明，说明统一导航补强、个人进度交互和手机/平板适配。
- 完整验证后合并到本地 `master`，再推送本地 `master` 到 GitHub 的 `main`。

## 8. 验收标准

1. 个人进度两类结果及阶段材料的装备名称均打开与查询分区一致的六项菜单。
2. 两类搜索结果均可修改锻造阶段，保存后当前搜索结果立即更新。
3. 材料需求说明使用实际持有装备名并组成一个连续句子。
4. 命中阶段按钮为实心同边框色、白字；对应材料表整行同步高亮。
5. 手机、平板、桌面指定视口无非预期横向溢出，菜单和返回入口可用，文本及触控尺寸合理。
6. 弟子顺序可通过两次点击交换；取消不保存，保存后完整记录按新顺序显示且调整界面收起。
7. 自动化测试、PWA 资源检查和本地页面实机流程均通过后才允许提交、合并和推送。
