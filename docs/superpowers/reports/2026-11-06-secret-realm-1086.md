# 1.0.86 秘境现金明细与期次折叠

## 已确认需求与根因

用户确认采用 A：每期显示独立的折后现金到分；方案总预算仍向上取整到元，单独说明差额，不改变方案排序。

旧版通过「累计费用取整预算减去上一条累计预算」分摊每行和每期的 `after`。1806 元礼包组合、4.3 折、三期无代金时，旧版分摊成 777 / 777 / 776，并非礼包价格真的不同。

## 实施

- 来源与期次分别从自己的折前净价计算 `discountedCash`，以 BigInt 有理数四舍五入到分；不借用其他期次或来源的舍入差额。
- 保留 `after`、`totalAfter` 原预算语义及最快/最省钱候选排序，新增展示字段，不改变库存、代金、购买次数及存储格式。
- 方案总览区分「折后金额合计」「总计折后预算（向上取整）」「预算取整差额」。统一去除明细格式化时再次 `Math.ceil` 到整元的处理，包括原价和代金小数。
- 示例的预期显示：三期均 776.58 元；合计 2329.74 元，预算 2330 元，取整差额 0.26 元。礼包、折扣或实际代金抵扣不同，明细仍允许有真实差异。
- 各期和来源独立显示到分；自定义折扣可能产生不足一分的金额，界面说明合计按未舍入金额计算，故不强行分配明细的显示舍入差。
- 所有期次详情默认关闭；各方案独立提供一键展开/收起。手动开关单期后同步按钮文案和 `aria-expanded`，使用 `aria-controls` 关联方案期次容器。部分展开时一键展开全部。
- 无期次的已达标空方案不显示无效按钮；折后金额及差额均为零。批量开关只修改 DOM，不保存、重算或影响其他方案。
- 详情按钮及 summary 最小触控高度 44px；PWA 版本资源统一更新为 1.0.86。
