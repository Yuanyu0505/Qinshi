# 机关兽资料与参考成本设计

## 已确认范围

- 保留正确名称「机关岳獠」「赤练王蛇」，补充全部机关兽来源；机关飞翼来源为尚同墨方。
- 增加材料获取说明、设计图掉落查询及幻音宝盒说明，不录入截图的固定攻略方案，不修改已有掉落。
- 单只、流派的每个方案显示参考成本，只计算觉醒神图和新增机关兽，不改变现有最优解、排序、逐只取整规则。
- 贡献折算统一为贡献除以 2.7，元宝整数结果向上取整。
- 神图默认单价 70，提供 64、70、134 和自定义；已有神图库存及使用开关按账号保存，各备选方案独立使用库存且不扣真实库存。
- 橙一至橙四按缺少碎片的贡献计算；橙五默认每只 45000 元宝可改；蓝紫手动填写单价，缺价不视为零。
- 所有改造、突破联合标签采用「（0改）7阶×13」。分列的改造表头不变。
- 幻音宝盒 30000 元宝获得六种设计图对应的成品各一件，仅说明，不参与计算。

## 数据与算法

在原有 MACHINE_BEAST_DATA 增加获取来源和材料目录；复用原有 runtime 文件，避免新增运行时资源及无关 PWA 版本变更。

纯函数 `normalizeReferenceCostSettings(data, raw)` 返回：

```js
{ awakeningBlueprintStock: 0, useAwakeningBlueprintStock: true,
  awakeningBlueprintPrice: 70, beastPrices: {} }
```

`beastPrices` 保存非贡献机关兽的每只参考单价；缺失橙五键使用 45000，显式 null 为未设置，蓝紫缺失为未设置。数字必须非负有限数，库存必须非负整数。

纯函数 `calculateReferenceCost(data, requirements, settings)` 接收：

```js
{ awakeningBlueprints: 0, beasts: [{ beastId, fragments: 0 }] }
```

返回神图需求、抵扣、缺口、费用，逐兽费用，缺价列表、已知小计和完整总价；仅完整时 `totalYuan` 为数值。每个方案汇总后只抵扣一次神图库存。

非贡献兽缺口按「缺少碎片 ÷ 每只碎片数 × 每只参考价」估算，不对折算只数额外取整；页面明确这是参考折算，不承诺实际购买包装。零缺口不要求填写价格。各费用元宝整数向上取整。

## 页面与保存

两类计算页面共用参考成本设置。只改价格、库存或开关时刷新已有成本，不重新求解、不消耗库存。输入无效时明确提示，不显示旧成本冒充新成本。

设置保存在 `qinshi_machine_beasts_progress_v1` 的 `referenceCost` 字段，与原 `beasts` 并存，兼容旧对象和旧裸兽映射。因此继续随原有账号隔离、导入导出、同步、清空流程走，不新增存储键。

保存返回 false 或抛错时明确报错，不假称保存成功。价格不进入优化器。
