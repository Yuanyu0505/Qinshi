# 关卡掉落橙色道具默认表设计

## 背景与目标

“关卡掉落”分区当前在未输入关键词时只显示“输入道具关键字开始查询”。本次新增一个固定的橙色道具默认表，方便直接查看指定橙装的普通关卡来源。

默认表仅用于未搜索状态；用户主动输入关键词后，仍然使用既有查询逻辑，完整展示普通关卡、英雄关卡和声望奖励。

## 固定数据

默认表固定为两列，按以下顺序展示：

| 道具名称 | 普通关卡 |
| --- | --- |
| 白羽绸衣 | 56-7、51-7 |
| 天问 | 56-5、51-5 |
| 醉梦 | 55-7、50-7 |
| 巨阙 | 55-5、50-5 |
| 纵横战袍 | 54-7、49-7 |
| 秋骊 | 54-5、49-5 |
| 苍云甲 | 53-7、48-7 |
| 墨眉 | 53-5、48-5 |
| 月华战袍 | 52-7 |
| 管事 | 52-5 |

关卡掉落数据后续不再更新，因此这些内容直接写入页面，不从 `DROP_DATA` 动态汇总，也不修改 `tools/build_drops.py`、`data/drops.js` 或 `js/drops.js`。

## 页面行为

1. `#drop-search` 为空时：
   - 显示固定橙色道具表。
   - 不读取或展示英雄关卡、声望奖励。
   - 清空现有搜索结果区域，不再显示“输入道具关键字开始查询”。
2. `#drop-search` 含任意非空关键词时：
   - 隐藏固定橙色道具表。
   - 调用现有 `DROPS.groupDrops(DROP_DATA, query)`。
   - 搜索结果照常展示普通关卡、英雄关卡和声望奖励。
3. 用户清空搜索框时：
   - 立即恢复固定橙色道具表。
   - 清空搜索结果区域。

搜索“白羽绸衣”等默认表内道具时，也必须进入现有完整搜索流程，而不是只展示默认表中的普通关卡。

## 结构与样式

- 在关卡掉落搜索面板下、`#drop-results` 上方新增独立容器 `#drop-default-orange`。
- 容器内使用语义化两列表格，表头为“道具名称”“普通关卡”。
- 道具名称复用橙装锻造已有类组合 `.mat.material-token.mat-orange`，表现为橙色填充、2px 橙色外框、白色字体。
- 普通关卡以普通文本或紧凑标签展示；不增加英雄关卡或声望奖励列。
- 表格在电脑端自适应内容宽度，在手机和平板端保持两列可读，不使整页横向溢出。
- 新增样式均限制在 `#partition-drops` 下，避免影响其他分区。

## 代码边界

预计修改：

- `index.html`：新增固定表容器与 10 行静态数据。
- `js/app.js`：登记容器元素，并在 `applyDrops()` 中切换默认表和搜索结果。
- `css/style.css`：新增固定表布局和移动端样式；道具高亮直接复用现有橙装样式。
- `service-worker.js`、`js/pwa.js`：将 PWA 版本从 `1.0.7` 提升至 `1.0.8`，确保已安装设备获取修改后的 HTML、JS 和 CSS。
- `serve.test.js`：补充静态 DOM、固定道具和 PWA 版本契约。

明确不修改：

- `tools/build_drops.py`
- `data/drops.js`
- `js/drops.js`
- 既有普通/英雄/声望搜索结果结构

## 错误与兼容处理

- 默认表是固定页面内容，不依赖数据加载和运行时汇总，不新增错误状态。
- 如果掉落数据加载失败，默认表仍可显示；主动搜索仍按既有错误边界处理。
- 不新增 localStorage 键，不改变备份格式。
- 桌面、Android、iPhone 和 iPad 使用相同行为。

## 验收重点

1. 首次进入关卡掉落时显示 10 行两列表格，不显示“输入道具关键字开始查询”。
2. 默认表只包含普通关卡，且道具顺序和关卡与本设计一致。
3. 道具名称使用橙装锻造同款橙色填充、2px 外框和白色字体。
4. 输入“白羽绸衣”后默认表隐藏，搜索结果完整显示普通关卡、英雄关卡和声望奖励分区。
5. 输入其他任意关键词时同样隐藏默认表；清空后恢复。
6. 手机和平板上两列表格不挤出页面。
7. PWA 更新到 `1.0.8` 后可加载新默认表。

项目约定由用户自行执行测试、lint、格式检查和手动验收；实施阶段只补充测试契约并列出建议命令，不主动运行验证。
