实施目标：在「其他资料 → 五行天枢录 → 气蕴与五极石」内，让用户一眼理解：选定一种气蕴，对应五行金木水火土分别需要多少数量；原图每行总计亦可查。页面显著呈现「五行属性所需气蕴数量」或「气蕴需求数量对照」，不再只用容易误解的“气蕴消耗”且没有解释。

具体要求：
- 直接复用既有 `elements-cost` 25行；新图已存在，不生成 `elements-cost-v2` 等新表。
- 保留姓名、品质、金、木、水、火、土、总计的顺序与原值；表头可写作“金属性所需”“木属性所需”等清楚标签，也可以保留金木水火土并在表格标题下放**一条短说明**：“各列数字表示对应五行属性所需的该气蕴数量。”不重复逐行说明。

## 5. P0 UI交互稳定性：搜索失焦后原图首次点击

基线 `other-reference-ui.js:99` 搜索 `input` 会调用 `results()`；通用 `change` 处理在100行，`results()` 会替换整个结果DOM（约91行），原图按钮由点击委托（93行）触发。资料包记录了手机搜索后第一次点击原图可能失效的采集现象，属待复现问题而不是已证明唯一根因。

- 先复现输入→直接点击「原图」；核查 `blur/change`、DOM重建、触控点击时序；不要在搜索框 `change` 且内容未实际变化时重复重绘结果。可针对 `data-ref-search` 在 `change` 分支做精确去重，其他 select 仍保持原行为。
- 保留搜索关键词、IME中文组合输入、按子栏目状态恢复；保留图片路径白名单、Esc关闭、缩放、双指、焦点恢复及跨模块关闭。
- 不允许 `try/catch` 吞错、整页刷新、取消原事件委托或修改搜索规则。实测手机和平板/桌面。
