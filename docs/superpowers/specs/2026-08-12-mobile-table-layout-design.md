# 手机和平板表格布局优化设计

## 目标

仅优化宽度不超过 `1024px` 的手机和平板布局，不改变桌面网页端现有布局。解决橙装锻造个人进度材料溢出、图鉴汇总装备信息过长，以及锻造和铭文表格滚动后缺少行列上下文的问题。

## 响应式范围

- 手机：视口宽度不超过 `767px`。
- 平板：视口宽度为 `768px` 至 `1024px`。
- 本次新增行为统一限定在 `@media (max-width: 1024px)` 内。
- 视口宽度大于 `1024px` 时沿用现有桌面样式和展示行为。

## 橙装锻造个人进度

个人进度内的阶段材料表使用卡片宽度内的两列布局：左侧显示锻造阶段，右侧显示该阶段所需材料。移动端和平板端覆盖全局表格的 `min-width: 860px`，并取消当前通过 `transform` 实现的左右位移。

阶段列保持紧凑且不换行，材料列使用剩余空间；多个材料可以在材料列中自动换行。完成全部阶段时，完成提示占据整行并保持在卡片内部。页面本身不产生横向滚动，用户无需缩放或左右滑动即可查看完整阶段和材料。

## 图鉴升级汇总

“当前结果升至 X 级汇总”中的绳结、魂魄、成长值及未达标数量继续默认显示。仅“所需装备”列表在手机和平板端默认折叠，并提供“展开所需装备”按钮；展开后按钮文案改为“收起所需装备”。

折叠状态只控制当前页面显示，不写入个人进度，也不影响筛选、目标等级或统计结果。每次汇总因筛选或目标等级变化而重新渲染时，手机和平板端恢复默认折叠。桌面端不显示该按钮，并始终展示装备列表。

当汇总没有待升级对象或没有装备需求时，不显示无意义的展开按钮。

## 锻造表格冻结规则

锻造材料总览和下方搜索结果表格在手机和平板端保留横向滚动，并允许表格容器在内容较高时纵向滚动：

- 第一行表头使用 `position: sticky; top: 0`。
- 第一列使用 `position: sticky; left: 0`。
- 左上角单元格同时固定在顶部和左侧，并使用最高层级。
- 固定单元格使用不透明背景，避免滚动内容从下方透出。
- 从第二行第二列（B2）开始的内容正常随横向和纵向滚动移动。

锻造材料总览的滚动容器为现有 `.summary-card`；搜索结果的滚动容器为现有 `.forge-scroll`。冻结样式只作用于这两类锻造表格，不影响其他分区。

## 铭文资料图表冻结规则

铭文“资料图表”中的天位主属性表和盾位副属性表沿用现有横向滚动容器。手机和平板端冻结第一行和第一列，左上角单元格同时冻结，层级与背景规则和锻造表格一致。

冻结样式限定在 `#inscription-reference` 内，避免影响铭文个人进度和查询筛选。

## 实现边界

- 修改 `css/style.css`，增加移动/平板端个人进度自适应和表格冻结样式。
- 修改 `js/app.js`，为图鉴汇总输出折叠区域及展开/收起按钮，并绑定事件委托。
- 不修改数据生成脚本、Excel 数据、个人进度存储键或备份格式。
- 不改动桌面端页面结构、表格尺寸、排序、搜索和筛选逻辑。
- 不引入新依赖。

## 手动验收重点

依据本项目工作方式，功能验证由用户手动执行。建议重点检查：

1. 手机竖屏打开橙装锻造个人进度，无需缩放和左右滑动即可看全每个阶段及材料。
2. 手机和平板进入图鉴，汇总装备默认折叠，按钮可以正确展开和收起；桌面端仍默认展开。
3. 手机和平板滚动锻造材料总览和搜索结果时，第一行、第一列及左上角单元格保持可见。
4. 手机和平板滚动铭文资料图表时，第一行和第一列保持可见。
5. 桌面宽度大于 `1024px` 时，上述页面与本次修改前一致。
