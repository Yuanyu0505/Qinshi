# 木人巷 1.1.50｜实施与验收

以 1.1.49 的 `bd0cc3b` 为当前基线，先运行执行包脚本对应的四个复现，再增量修改。没有覆盖仓库，游戏数据文件、账号存储键 `qinshi_wooden_man_alley_progress_v1`、进度 JSON 格式及账号权限接口均未改变。

## P1 / P2

- Worker 故障时报告未完成并可重试，不把木人巷求解退回主线程。仍保留其他轻量模块原有降级逻辑。
- 结果区分已找到候选、不足与未知。反向只用有证据的不足收紧上界；尚不能证明的情况显示已找到层数和上界。独立审查补测了小棋盘炸药模型的精确下界，反向也明确标注所选风险口径，不把期望或保守估计当作通关保证。礼包拆开人民币、购剑元宝、券及秘匣；秘匣不折为木剑。保守系数仍为 1.2。
- 个人进度突出棋盘，格子增加行列可访问名称，礼包折叠；目标计算改用 13 项快捷目标选择框和 5 段可展开限制；资料表手机补列名。输入节点、焦点、展开状态保留。CSS 局部限定木人巷。
- 确认前版的机关兽历史对照有两项旧断言：1.1.49 已调整库存分配及渲染入口。回归继续对照方案、完整前沿和分页，同时单独验证变更后的资源守恒；未修改本轮范围外的机关兽运行代码。

## 实测

- 隔离桌面 Edge：320×568、390×844、820×1180、1366×768、1920×1080，另测 200% CSS 缩放。保有全部 49 格、13 项快捷目标、20 个礼包字段与 30 组分段限制；320px 方格实测约 36.3×36.3 CSS px，820px 的棋盘和操作并列，结果与资料无模块内横向溢出。实测前后截图在交付附件中。
- 浏览器木人巷与 PWA 共 **25/25**。Node 24 合成 500 层样例：正向约 60ms，反向约 116ms（资源样本含木剑、6 类辅助道具、券及礼包；非低端手机实测）。
- 最终全量单元测试 **1291/1291**，零失败、零跳过。
- 同一桌面 Edge CPU 4× 限速，每个宽度和 Worker 条件 10 次；端到端含点击与渲染：正常 Worker 320px P50/P95 约 716/1050ms，390px 约 687/1183ms；故障时 320px 约 226/380ms，390px 约 247/324ms。故障场景仍有渲染长任务，不能宣称零长任务。测试只读 renderer JS 堆的约 11MiB 峰值，不是 Worker 进程峰值或物理手机结果。
- 依 GitHub Pages 工作流组装候选静态站点，核对 **249 个资源引用**。版本文件、HTML、加载器、PWA 与缓存版本同步到 1.1.50。
