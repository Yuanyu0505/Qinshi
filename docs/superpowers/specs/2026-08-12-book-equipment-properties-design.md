# 典籍装备属性设计

## 目标与范围

在现有“装备属性”分区中加入《秦时相关（更新贯侯钟离昧）20260618.xlsx》“典籍属性”子表格的数据，支持普通典籍与神兵典籍的搜索、分类、主属性、副属性和排序，并按档次、阶次完整展示属性。

本次只更新电脑网页端的数据、查询规则和展示效果，不专门调整手机或平板端布局。

## 数据来源与分类

- 数据源：工作簿“典籍属性”工作表 `A1:T53`。
- `A2:A19`：初始紫色典籍，归入“典籍”分类。
- `A20:A40`：初始橙色典籍，归入“典籍”分类。
- `A41:A53`：神兵典籍，归入“神兵典籍”分类。
- 界面分类按钮顺序：`除典籍外 → 武器 → 防具 → 饰品 → 典籍 → 神兵武器 → 神兵防具 → 神兵饰品 → 神兵典籍`。
- 原“装备分类：不限”改名为“除典籍外”，并作为默认分类状态。
- “除典籍外”严格排除“典籍”和“神兵典籍”。即使搜索框输入典籍名称，也不会返回典籍；用户必须明确选择“典籍”或“神兵典籍”才能查询典籍数据。
- “典籍”分类按钮只匹配 `A2:A40`，“神兵典籍”分类按钮只匹配 `A41:A53`。需求描述中未特别区分时，“典籍”泛指两个分类的合集。

## 数据模型与生成

继续使用现有 `SPECIAL_EQUIPMENT_DATA` 数据入口，在原装备记录结构上扩展典籍专用的分阶数据，不建立重复的查询系统。

- 原装备继续使用每个档次下的平铺属性 token。
- 典籍在每个档次下保存有序阶次：`[{ stage: 0, tokens: [...] }, ...]`。
- 每个 token 保存统一后的内部属性名、数值、展示文字和必要的复合匹配信息。
- 数据生成工具同时读取“特殊属性装备”和“典籍属性”工作表，一次生成完整的装备属性数据文件。
- 初始紫色典籍拥有紫色、橙色、橙金、红色、红金五档。
- 初始橙色典籍和神兵典籍没有紫色档，不生成或展示空的紫色档。
- 紫色、橙色档仅包含 `0阶、5阶、10阶`；橙金、红色、红金档包含 `0阶、5阶、10阶、15阶`。
- Excel 中的空值和 `-` 作为无属性状态处理，不参与筛选或排序。

## 主属性规则

- 每件典籍有两个主属性，其中一项固定为“内力”，另一项为“攻”“防”或“血”。
- 界面不新增“内力”主属性按钮。
- 选择“攻”“防”“血”时，典籍按另一项主属性匹配。例如“典籍 + 攻”只返回主属性为“攻、内力”的典籍。
- 典籍结果中的主属性完整展示为“攻、内力”“防、内力”或“血、内力”。

## 副属性标准化

装备属性全分区统一使用以下内部副属性名称：

`攻、血、防、攻防血、穿透、暴击、暴伤、技伤减免、抗暴、速、闪避、招架、敌方减攻、敌方减防、敌方减血`

具体规则：

- 原装备和典籍中的“减伤”“减免”统一归类并展示为“技伤减免”。
- “速度”筛选按钮及内部属性名使用“速”，数据按 `150速` 等原有形式展示。
- Excel 中 `敌方-4%攻`、`敌方-3.6%防`、`敌方-2%血` 分别归类为“敌方减攻”“敌方减防”“敌方减血”，展示时保留原格式。
- 普通属性统一使用数值在前、名称在后的格式，如 `35%暴击`、`20%技伤减免`、`10%攻防血`。
- `10%攻防血` 同时满足“攻”“防”“血”“攻防血”四个副属性条件。
- 同一个“攻防血”token 可以同时满足多个已选条件。例如同时选择“攻”和“防”时，单个“攻防血”token 即可满足这两个条件。
- `攻防血` 参与单项排序时使用相同数值；例如 `23%攻防血` 在“攻”排序中按 23 计算，但排序值仍显示真实来源 `23%攻防血`。

经核对“典籍属性”工作表，除上述列表外没有遗漏的新副属性分类。

## 筛选与排序

- 副属性选择数量不设上限。
- 多个副属性采用 AND 关系，装备必须满足全部已选条件。
- 选择多个副属性后，默认用第一个已选副属性排序。
- 用户可以在“排序属性”区域切换为任一已选副属性；移除当前排序属性后，自动改用剩余条件中的第一个。
- 取值档位顺序：`最高值 → 橙金 → 红色 → 红金`。不增加紫色和橙色取值按钮。
- “最高值”跨装备全部颜色档次和全部阶次取目标副属性的最大值。
- 选择橙金、红色或红金时，在对应档次的全部阶次内取目标副属性的最大值。
- 取值档位只决定排序值来源，不额外限制结果。例如装备在橙金档没有目标属性时仍保留，排序值显示“—”并排在有数值的结果后面。
- 排序值显示真实命中 token：`150速`、`35%暴击`、`23%攻防血`、`敌方-4%攻`等。

## 电脑网页端展示

### 原有装备

- 原武器、防具、饰品和神兵装备仍使用现有四档表格：橙色、橙金、红色、红金。
- 不为原有装备增加或显示紫色列。

### 典籍分类

选择“典籍”时，搜索、主属性、副属性和排序条件统一作用于两组数据，但结果分成上下两个表格：

1. 上方“初始橙色典籍”：只显示橙色、橙金、红色、红金。
2. 下方“初始紫色典籍”：显示紫色、橙色、橙金、红色、红金。

筛选后没有结果的分组直接隐藏，不显示空表或占位内容。

### 神兵典籍分类

- 选择“神兵典籍”时使用一张结果表。
- 只显示橙色、橙金、红色、红金，不显示紫色列。

### 阶次布局

- 每件典籍仍占结果表中的一整行。
- 每个颜色档次占一个列区域。
- 档次内部每个阶次占一小行，按 `0阶 → 5阶 → 10阶 → 15阶` 纵向排列。
- 紫色、橙色只展示 `0阶、5阶、10阶`；其余档次展示四个阶次。
- 阶次没有属性时保留该阶次小行并显示“—”，便于横向对照。
- 档次内若同一阶次包含多个属性，则在该阶次小行中完整展示全部属性。

## 默认顺序

- 选择“典籍”时，上方初始橙色典籍、下方初始紫色典籍。
- 未选择副属性时，各组保持 Excel 原始行序。
- 选择副属性后，各组分别按当前排序规则降序排列；排序值相同时保持 Excel 原始行序。
- 两个普通典籍分组之间不跨表混合排序。
- 神兵典籍未选择副属性时保持 Excel 原始行序，选择副属性后按同样规则排序。

## 兼容与错误处理

- 不更改其他既有分区的数据和行为。
- 不改变原有装备分类、搜索、主属性筛选和表格展示，只扩展其数据标准化、无限副属性选择以及取值档位。
- 数据生成阶段发现无法识别的典籍属性格式时，应报告具体工作表、单元格和原始内容，并停止生成，避免静默丢失数据。
- 典籍无紫色档时不生成伪造档次，也不以空白紫色列占位。
- 本次不新增浏览器存储字段，不影响用户已有个人进度。

## 建议用户手动验证

- 默认“除典籍外”是否完全排除两类典籍，包括搜索框直接输入典籍名称的情况。
- “典籍”与“神兵典籍”分类是否分别只包含规定的 Excel 行段。
- “典籍”结果是否按“初始橙色在上、初始紫色在下”分组，空组是否隐藏。
- 三类典籍是否展示正确的颜色档次和阶次，且一个阶次一小行。
- 主属性“攻、防、血”是否正确匹配第二主属性，并完整显示固定的“内力”。
- “技伤减免”“速”“敌方减攻/减防/减血”是否正确归类和显示。
- “攻防血”是否能命中四类副属性、同时满足多个条件并正确参与排序。
- 副属性能否不限数量选择，并始终采用 AND 关系。
- “最高值、橙金、红色、红金”是否按对应档次全部阶次的最高值排序，无档位值的结果是否保留在末尾。
- 原有装备是否继续使用四档表格，并且全分区的“减伤/减免”已统一为“技伤减免”。
- 其他分区及已有个人进度是否保持不变。
