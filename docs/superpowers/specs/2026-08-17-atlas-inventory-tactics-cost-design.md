# 图鉴个人库存与兵法综合元宝计算设计

## 1. 目标与范围

本次在不更新 PWA、不推送 GitHub 的前提下完成三项改动：

1. 对工具运行数据统一纠正 `墨梅 → 墨眉`、`惊倪 → 惊鲵`，并在数据生成器入口固化标准化规则，避免重新生成后复发。
2. 仅为已收藏图鉴增加魂魄库存、逐阶段装备拥有状态和备注编辑；未收藏图鉴保持只读且不展示个人库存。
3. 为兵法增加“兵法详情／计算”子分区，修正逐阶熟练度号角逻辑，并提供六兵法库存、购买包和元宝综合计算。

每项功能完成后单独提交并快进合并到本地 `master`。用户当前未提交的 Excel 工作簿和 `答题.jpg` 必须保留，不纳入提交。

## 3. 总体架构

沿用现有模块边界，不增加通用库存框架：

- 图鉴纯计算和库存规范化扩展 `js/atlas.js`，图鉴 DOM、事件和本地存储接入 `js/app.js`。
- 兵法纯计算扩展 `js/tactics.js`，子分区、表单、本地存储和渲染扩展 `js/tactics-ui.js`。
- 样式集中在 `css/style.css`，桌面端使用表格和分栏，手机/平板使用单列卡片。
- 新存储键以 `qinshi_` 开头，自动兼容现有 `js/settings.js` 的备份、导入和清除逻辑。

不修改现有图鉴等级、图鉴收藏和兵法个人进度的数据格式。

## 4. 错别字标准化

### 4.1 生成规则

生成器使用明确的文字映射：

```text
墨梅 → 墨眉
惊倪 → 惊鲵
```

图鉴生成器对弟子、获取途径、所属图鉴和装备名称等输入文本统一调用标准化函数；锻造生成器对主装备和材料装备名称统一调用标准化函数。映射仅修正已确认错别字，不做模糊替换。

### 4.2 输出要求

- “神·侠道天明”9→10 阶装备显示为“墨眉”。
- 锻造数据中所有“惊倪”显示为“惊鲵”。

- 历史说明文档中作为数据示例的错误写法同步改正，避免后续维护人员误用。

## 5. 已收藏图鉴个人库存

### 5.1 存储结构

新增存储键：

```text
qinshi_atlas_inventory_v1
```

结构按图鉴 ID 保存：

```js
{
  "atlas-item-id": {
    soulsOwned: 760,
    equipment: {
      "9→10|0": {
        name: "墨眉",
        owned: false,
        note: "还差声望兑换"
      }
    }
  }
}
```

装备键由升级阶段和该阶段装备序号组成，同名装备出现在不同阶段时互不影响。记录同时保存装备名称，读取时若阶段位置仍在但装备名称已变化，则视为新需求并使用默认未拥有状态，防止数据更新后错误套用旧状态。

取消收藏只隐藏库存信息，不删除存储；再次收藏恢复。旧备份没有此键时使用空对象。

### 5.2 规范化与校验

- `soulsOwned` 为非负整数；空输入表示未填写，不强制保存为 0。
- `owned` 只接受布尔值。
- `note` 保存字符串，渲染时执行 HTML 转义。
- 未知图鉴 ID、未知装备阶段和多余字段在读取时忽略，不影响页面。
- 存储失败时保留编辑界面和用户输入，显示明确错误，不伪装成保存成功。

### 5.3 交互

已收藏图鉴卡片显示“编辑库存”；未收藏图鉴没有编辑按钮，也不展示已有魂魄、装备状态或备注。

编辑模式：

- 魂魄后显示非负整数输入框。
- 当前等级到目标等级区间内的每件装备分别选择“已拥有／未拥有”。
- 未拥有时显示备注输入；已拥有时隐藏备注但保留原值。
- “保存”写入本地存储；“取消”放弃本次草稿。

只读模式：

- 需求 765、库存 760：`魂魄 765（已有760，还差5）`。
- 库存不少于需求：`魂魄 765（库存达标）`。
- 未填写库存：保持 `魂魄 765`。
- 已拥有装备在装备标签后显示绿色底色、粗体 `√`。
- 未拥有且有备注时显示备注；无备注时显示“未拥有”。

当前等级或目标等级变化后，只渲染仍在目标区间内的装备记录；暂时隐藏的历史记录继续保留。顶部“当前结果升至 X 级汇总”始终表示完整升级需求，不扣除个人库存。

## 7. 兵法逐阶计算修正

### 7.1 进阶材料

兵法起点 `start`、终点 `target` 满足 `0 ≤ start ≤ target ≤ 15`。印记、功勋和表格进阶号角累计区间为：

```text
(start, target]，即 start + 1 至 target
```

起点等于终点时没有进阶材料。

### 7.2 风林火山熟练度演练

从 `start` 进阶至 `target` 必须完成 `start` 至 `target - 1` 每阶熟练度：

- 起点阶读取或输入 `rehearsalSpent`，只扣除本阶已消耗号角。
- 后续中间阶从 0 开始。
- 不计算目标阶自身演练。
- 阴、雷不计算熟练度演练。

完整一阶：

```text
runs = ceil(guaranteeHorn / singleHorn)
actualHorn = runs × singleHorn
```

起点阶剩余：

```text
remainingRuns = ceil(max(0, guaranteeHorn - rehearsalSpent) / singleHorn)
remainingHorn = remainingRuns × singleHorn
```

例如 5→8 阶，演练 5、6、7 阶，不演练 8 阶。单兵法详情和综合计算共用同一纯逻辑函数，防止口径分叉。

### 7.3 真言碎片

真言累计区间为 `(真言起点, 真言终点]`；未激活 `-1` 到 0 阶包含激活碎片。真言终点不得低于起点，也不得超过目标兵法阶允许上限。

共享材料：

- 风、林、火、山的统真言碎片共用库存和购买包配置。
- 风、林、火、山的极真言碎片共用库存和购买包配置。

独立材料：齐、镖、灵、禅、心、解、裂、洽、殇、盛真言碎片。

## 8. 综合计算存储

新增存储键：

```text
qinshi_tactics_cost_calculator_v1
```

保存：

- 六种兵法参与勾选状态。
- 每种兵法起点、终点、起点阶已消耗号角和每种真言起止阶。
- 功勋、号角、统碎片、极碎片共享库存。
- 六种印记库存。
- 其余真言碎片独立库存。
- 每种材料的 `packSize` 和 `packPrice`。

首次进入时起点读取兵法个人进度，终点等于起点，六种兵法默认全部参与。之后恢复全部保存内容。“从个人进度重新读取”只覆盖六种兵法及真言起点和起点阶已消耗号角；终点、参与状态、库存和购买包配置保持不变。

所有数量为非负整数；每包数量填写时必须大于 0；每包元宝为非负整数。无效值保留在编辑状态并显示错误，不写入规范化存储。

## 9. 购买包与元宝公式

对每种材料：

```text
shortage = max(0, demand - stock)
packs = shortage === 0 ? 0 : ceil(shortage / packSize)
yuan = packs × packPrice
leftover = stock + packs × packSize - demand
```

点击计算只做模拟，不扣减库存。

若缺口大于 0 且每包数量或价格未设置：

- 继续显示需求、库存和缺口。
- 标记“价格未设置”。
- 只累计已定价材料小计。
- 总结果显示“总价未完整”，不得把空价格当作 0。

## 10. 单兵法与全部合计

每种已勾选兵法显示两类结果：

1. 原始需求：进阶材料、逐阶演练号角和真言碎片。
2. 独立估算：假设只培养该兵法，使用全部当前共享库存后需要购买的材料包和元宝。

全部合计先汇总所有已勾选兵法需求，再对功勋、号角、统碎片和极碎片各扣除一次共享库存。各兵法独立估算都可使用完整共享库存，因此六个单项价格之和不保证等于全部合计；界面明确说明这一点。

## 11. 响应式界面

桌面端：

- 六兵法起止设置采用紧凑表格或双列卡片。
- 库存与购买包使用材料表格。
- 结果按兵法卡片和总计表格展示。

手机和平板：

- 六兵法设置变为单列卡片。
- 每种材料变为“库存／每包数量／每包元宝”的单材料卡片。
- 结果卡片纵向排列，不依赖横向滚动才能读取关键数字。
- 按钮和输入保持至少 44px 触控高度，数值输入使用 16px 字号防止移动浏览器自动缩放。

本次只准备响应式代码，不提升 PWA 版本、不修改 Service Worker、不推送 GitHub。
