# 多游戏账号档案系统设计

## 目标

为 Qin 工具增加最多三套、彼此完全隔离的游戏账号数据。任意时刻每个浏览器标签页只展示一个账号的数据；玩家可以切换、编辑、排序、清空和删除账号，并指定主账号。完整备份和云同步继续以“整台设备全部工具数据”为单位工作。

## 已确认规则

- 最多三个账号。
- 每个账号包含玩家自定义的“账号名称”和“服务器”，两者组合必须唯一。
- 全部游戏进度、库存、收藏、禁地勾选及常用弟子等个人数据按账号隔离。
- 静态资料、PWA 状态、云同步凭据和纯界面偏好保持全局。
- 全局入口负责快速切换；设置页负责完整管理。
- 主账号固定排在第一位；其他账号支持手动交换顺序。
- 设为主账号不立即切换当前标签页。
- 新标签页和重新打开工具时默认进入主账号；当前标签页刷新及切换触发的重载保留当前账号。
- 不同标签页可使用不同账号；同一账号同时只能由一个标签页编辑，其他标签页只读并可接管编辑权。
- 清空、删除、导入前自动下载包含全部账号的完整备份。
- 允许删除任意账号和最后一个账号；无账号时进入初始化页。
- 删除主账号后由创建时间最早的剩余账号接任；删除当前账号后切换到主账号。
- 旧本机单账号数据自动迁移为“默认账号 / 未填写”并设为主账号。
- 旧版 JSON 备份允许迁移后整体覆盖；旧版云快照拒绝覆盖，要求来源设备先升级并重新上传。
- 新版 JSON 导入和云同步都整体覆盖当前设备，不合并账号。

## 架构

### 账号注册表

全局注册表保存在 `qinshi_accounts_v1`，结构如下：

```js
{
  schemaVersion: 1,
  primaryAccountId: "uuid",
  order: ["primary-uuid", "other-uuid"],
  accounts: [
    {
      id: "uuid",
      name: "主号",
      server: "微信一区",
      createdAt: "2026-09-23T00:00:00.000Z",
      updatedAt: "2026-09-23T00:00:00.000Z"
    }
  ]
}
```

账号 ID 创建后不可变。注册表规范化时强制主账号位于 `order[0]`，剩余账号按玩家保存的顺序排列。名称和服务器去除首尾空格后不能为空，组合比较使用规范化后的文本。

### 账号数据命名空间

现有逻辑键保持不变，例如 `qinshi_forging_progress_v1`。物理存储键改为：

```text
qinshi_account_v1:<accountId>:<logicalKey>
```

新增 `js/account-profiles.js` 提供统一接口：

```js
getItem(logicalKey)
setItem(logicalKey, value)
removeItem(logicalKey)
listAccountData(accountId)
replaceAccountData(accountId, data)
clearAccountData(accountId)
createAccount(input)
updateAccount(accountId, patch)
setPrimary(accountId)
reorderAccounts(order)
deleteAccount(accountId)
switchAccount(accountId, returnState)
```

业务模块不再直接通过 `localStorage` 访问个人数据，而是调用上述门面。门面启动时捕获当前标签页账号，不因其他标签页切换而改变。

### 当前标签页和主账号

- 当前标签页 ID 和当前账号 ID 保存在 `sessionStorage`。
- 新标签页没有会话账号时选择主账号。
- 手动切换写入目标账号和返回分区后重新加载。
- 普通刷新保留该标签页当前账号。
- 账号被删除或失效时回退到主账号；没有账号则进入初始化模式。

## 旧数据迁移

旧逻辑键是以 `qinshi_` 开头、但不属于注册表或账号命名空间的游戏数据键。首次启动新版时：

1. 收集全部旧游戏键和值。
2. 生成“默认账号 / 未填写”。
3. 把旧键写入新账号命名空间并逐项读回校验。
4. 写入账号注册表作为提交点。
5. 删除已迁移旧键。

若写入或校验失败，不写注册表、不删除旧键；下次启动可重试。迁移函数幂等，注册表存在后不会重复创建账号。

## 账号管理流程

### 创建与编辑

- 无账号时显示阻断式初始化页，创建成功后成为主账号和当前账号。
- 已有账号时从设置页创建，达到三个后禁用创建。
- 名称和服务器组合重复时拒绝保存。
- 修改名称和服务器只更新元数据，不移动或重写账号数据。

### 切换

- 全局切换器展示 `账号名称 · 服务器`，当前账号高亮，主账号带标记。
- 切换前记录当前分区和必要返回状态。
- 目标账号写入当前标签页会话后重新加载，并恢复原分区。

### 清空

1. 玩家点击清空。
2. 工具先触发全部账号完整备份下载。
3. 玩家输入目标账号名称确认。
4. 删除该账号命名空间下全部游戏数据，保留账号元数据、排序和主账号身份。
5. 清空当前账号时重新加载原分区。

### 删除

1. 工具先触发全部账号完整备份下载。
2. 玩家输入目标账号名称确认。
3. 删除账号全部物理数据和注册表条目。
4. 若删除主账号，最早创建的剩余账号接任并置顶。
5. 若删除当前账号，当前标签页切换到新主账号并重新加载。
6. 删除最后一个账号后进入初始化页。

## 多标签页编辑权

每个账号使用运行时租约键和 `BroadcastChannel` 协调编辑权。租约不以 `qinshi_` 开头，因此不进入备份和云同步。

- 标签页进入账号时尝试取得编辑租约。
- 已有其他有效租约时进入只读模式。
- 只读标签页可以接管；接管写入新的租约所有者并广播。
- 原编辑标签页收到广播后立即变为只读。
- 存储门面的每次写入都重新校验租约所有者；即使广播延迟，旧标签页也不能继续写入。
- 标签页定期续租，并在 `pagehide` 时主动释放；异常关闭后的租约可过期。
- 只读模式允许查询、筛选、导航和查看数据，阻止持久化写入并显示固定提示。

## 备份与导入

JSON 备份格式升级为版本 2，仍以字符串键值映射作为底层数据：

```js
{
  formatVersion: 2,
  appName: "Qin",
  reason: "manual",
  exportedAt: "ISO time",
  data: {
    qinshi_accounts_v1: "...",
    "qinshi_account_v1:<id>:qinshi_forging_progress_v1": "..."
  }
}
```

- 新版校验注册表、账号数量、ID、主账号、顺序、名称服务器唯一性和物理键归属。
- 新版导入整体替换所有受管数据，失败时恢复旧值。
- 版本 1 JSON 文件先转换成单个默认账号的版本 2 数据，再整体覆盖。
- 自动备份必须成功触发后，清空、删除或导入才继续。

## 云同步

现有云同步继续调用 `QinshiSettings.collectManagedData()`，因此新版快照自动包含全部账号。拉取或历史恢复在覆盖前增加多账号格式验证：

- 包含合法 `qinshi_accounts_v1` 的快照才允许覆盖。
- 缺少注册表的旧云快照显示明确错误，不自动迁移。
- 覆盖前的本设备数据仍作为最新历史快照上传。
- 最近三次历史快照和端到端加密规则不变。

## 界面

- 桌面端切换器位于左侧导航顶部。
- 手机和平板端使用页面顶部按钮和底部抽屉。
- 设置页新增账号卡片、创建、编辑、设为主账号、清空、删除和排序界面。
- 主账号固定第一位；排序模式中只允许交换非主账号。
- 只读模式显示账号名称和“只读”状态，提供“接管编辑权”。
- 无账号时显示独立初始化页，不渲染普通功能分区。
- 所有交互满足现有手机和平板触控尺寸和安全区规则。

## 错误处理与一致性

- 所有注册表写入前先完成规范化和校验。
- 创建、迁移、导入和替换采用“先写数据、后写注册表”的提交顺序。
- 浏览器空间不足时保留原数据并显示可操作错误。
- 达到三个账号、重复名称服务器组合、无效备份或非法物理键都拒绝操作。
- 未来新增个人数据必须使用账号存储门面；测试禁止新增业务模块直接写入个人 `localStorage` 键。

## 验收范围

- 三个账号在所有个人数据分区中完全隔离。
- 主账号、切换、初始化、排序、清空和删除流程正确。
- 旧本机数据和旧 JSON 正确迁移；旧云快照被拒绝。
- 新版完整备份及云快照可在设备间整体覆盖。
- 双标签页只读、接管和异常关闭恢复正确。
- 桌面、手机和平板入口和管理界面均可用。
- 项目约定由用户运行测试、构建和实机验收；实现方只更新测试约束，不主动执行。
