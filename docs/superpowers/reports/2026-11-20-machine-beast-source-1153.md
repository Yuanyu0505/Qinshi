# Qin 1.1.53｜机关兽库存来源分配

基线 `ded26ef`（运行代码 1.1.52）。执行包四组截图的配置已转为真实数据夹具，使用 `mechanical-yueliao`、橙五、当前研发度 0、25 级目标、无改造及碎片，库存每档限用 1。保持 1.1.52 检查点和工作区无关文件。

## 根因与处理

`js/machine-beasts.js` 的 `allocateConvertedInventory` 原来先抢占所有同形库存，然后依候选生成顺序分配剩余库存：0 阶及 6 阶可先于 7 阶耗掉折算额度。主前沿的研发度、逐只资源、折算数量均正确，错误在同一最终组合的来源分派。现在先保留不可替代的原形，再按最终阶数为自由模式计算库存份额，随后只在该阶已分到的份额内安排同形直投与加工。对固定向量，高阶份额取剩余预算与该阶需求的最小值；普通 0–7 阶库存来源在自由域内等价，低阶不能抢占高阶份额。高阶拆分、限用和神核结算仍由共享分配器处理。

来源以兽 ID、原阶和改造档标识，记录实际供给的目标阶数、改造和折算本体数，以及返核和余量。核心路径在单兽、流派和同等分页共用。高阶混合重组按本体份数展示，避免误把同一成品算作多个成品。界面显示最终投入组合、原形→拆分→各路投入和余量；神核结算独立，不与突破材料混记。

## 核验和边界

- 四组各核对来源、最终投入、参考元宝、神图、研发度、溢出、路径、本体及神核守恒、余量、输入不变；另测候选顺序置换与高阶直投互斥。历史差分比较正式结果、最终形态与分页；来源字段允许变化，但账本守恒仍单独断言。
- 尚无已核实的降阶材料返还数据；“仅0阶”仍不能凭空升阶，不宣称已解决返料升阶。对于同阶且满足神核及本体限制的多个来源，本轮保留稳定来源选择，不承诺跨所有返核组合全局最少拆解次数。
- 正式指标全相等时，单兽仍按重新分配后的来源条目稳定破同分；静态审查表明特制的不同终态同分案例可能因此换首选终态，不影响正式指标。四组真实回归的最终投入形态均未变。
