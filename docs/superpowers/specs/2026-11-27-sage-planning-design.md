# 小圣贤庄需求与计算规则

用户于2026-11-27确认本轮需求及两项计算口径，按当前工作区继续实施。

- 周期固定27天、4次周任务；同一项目同一日／周只取达到条件的最高档奖励。
- 正向估算使用离散档位下拉框，默认各项目最高档，宗师为可选3倍，最终统一向下取整。
- 充值任务经验与每充值1元的额外经验分项显示，不重复计入。用户确认宗师为198元购买且计入累计充值，填写／规划的充值金额已包含该款；仅修订说明，不自动另加198元。
- 商城层级为0、60、180、300。用户后续更正为累计消费门槛：进入第二／三／四层之前，所有已解锁前层累计消费须达到60／180／300。未解锁层的购买不可用于解锁自身。
- 每项需求单位为兑换次数，整数且不得超过限购；勾选与数量仅保留在当前页面内存，跨筛选保留，不保存账号。
- 选中后层商品且前层消费不足时，列出缺口，不生成可行的反向方案；不暗自添加商品补齐门槛。
- 反向需求经验为ceil(总价×100／宗师倍率)。优先级为体力、活跃、元宝消费、周充值、额外充值；某来源不足时先用满再使用下一来源。
- 允许27天／4周内各次选不同档位。来源内用有界动态规划选择足够经验且溢出最少的组合；经验相同优先总投入较少，再优先参与次数较少。
- 周充值档位产生的每元额外经验随该档实际充值一起计入；最后的额外充值仅补尚缺经验，不再次领取周充值任务。
- UI移除用户指定两句历史说明。商城每行需求控件不换行；估算控件桌面同排、手机局部横向滚动；规则项目压缩为短标题，原始细节完整保留到规则列，数字列表用顿号。

## 方案取舍

复用现有纯计算模块和资料UI，不新增账号存储或依赖。使用有界精确枚举／动态规划而非按平均日值反推，才能支持“做几天／几周”与档位离散约束。

## 边界

未知商品、非整数／超限兑换数必须报错；空需求不产生任务方案。资料生成脚本同步修订，避免重建资料回退。
