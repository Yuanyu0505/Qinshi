# Qin 跨设备云同步设计

日期：2026-09-11
状态：已完成需求确认，等待用户审阅规格

## 1. 背景

Qin 当前是部署在 GitHub Pages 上的纯静态 PWA。个人进度以 `qinshi_` 为前缀保存在浏览器 `localStorage` 中，并通过设置页手动导出或导入 JSON 文件。跨设备迁移需要反复下载、传递和导入备份文件，操作繁琐。

本功能新增一个只供用户本人多台设备使用的免费云同步能力。同步采用“设备快照模式”：每台设备维护自己的完整快照，目标设备明确选择一个来源设备，再用来源设备的全部数据覆盖本机；系统不自动合并不同设备的数据，也不根据时间戳自动猜测同步方向。

## 2. 目标

- 在 Windows、iOS、Android 平板等设备之间手动同步全部个人数据。
- 保持一个明确、可解释的“来源设备 → 当前设备”覆盖方向。
- 同步工具当前以及未来所有以 `qinshi_` 开头的数据。
- 同步前先保证当前设备运行最新工具版本，新模块代码与新模块数据同时到位。
- 所有个人数据在客户端加密，云端只保存密文。
- 每台设备保留一个最新快照和最近三个历史快照。
- 覆盖本机前同时生成本机 JSON 备份，并把覆盖前数据保存为当前设备最新一条历史快照。
- 云端故障、网络中断、版本不兼容或写入失败不得破坏本机数据或已有云端快照。
- 只使用 Cloudflare Workers Free 与 D1 Free；不启用付费计划、超额计费或其他付费依赖。

## 3. 非目标

- 不做后台自动同步、定时上传或推送同步。
- 不做设备之间的点对点连接。
- 不做模块级或记录级数据合并。
- 不向其他用户开放公共注册、共享空间或协作编辑。
- 不通过云同步分发业务代码；业务代码仍由现有 GitHub Pages PWA 发布链路更新。
- 不取消现有 JSON 导入、导出功能。

## 4. 总体架构

系统分为三层：

1. GitHub Pages PWA：继续承载工具代码、内置资料和界面；新增云同步界面、加密模块和同步协调器。
2. Cloudflare Worker：提供受限的 HTTPS API，完成认证、设备管理、上传会话、快照读取、事务提交和历史清理。
3. Cloudflare D1：保存空间、设备、令牌摘要、加密密钥包装、加密快照及分块。数据库不保存密码、恢复密钥、设备令牌、主密钥或个人数据明文。

PWA 与 Worker 使用跨域 HTTPS 通信。Worker 只允许正式 GitHub Pages 地址和明确配置的本地开发地址访问。云端不可用时，PWA 的全部本地功能与 JSON 备份功能仍可正常使用。

## 5. 用户模型与设备模型

### 5.1 同步空间

同步空间只属于一个用户，但不要求注册账号。首次创建时生成：

- 128 位以上随机同步码，用于定位同步空间。
- 用户设置的同步密码。
- 256 位随机主密钥，用于加密设备名称和全部快照。
- 256 位随机恢复密钥，用于密码丢失时重新包装主密钥。

同步码可以公开输入，但单独拥有同步码不能读取、解密或修改数据。

### 5.2 设备

每台浏览器安装或浏览器配置视为一台独立设备，拥有：

- 随机设备 ID。
- 用户可编辑的设备名称；首次绑定时依据平台生成“Windows 设备”“iPhone 设备”“Android 平板”等默认值。
- 独立随机设备令牌；Worker 仅保存令牌摘要。
- 最新快照、最近使用时间、最后上传时间和撤销状态。

设备令牌被撤销后，该设备不能再访问云端。服务端无法远程删除丢失设备中已经存在的本地数据。

### 5.3 本机凭据

首次用密码完成配对后，本机在 IndexedDB 中保存设备 ID、设备令牌和主密钥，不保存密码明文。设置页提供“忘记本设备”，用于删除本机云同步凭据但不删除个人进度。

浏览器 PWA 无法跨平台统一使用硬件安全区；若已解锁设备的完整浏览器配置被窃取，本机凭据仍可能被利用。用户可以从另一台设备撤销该设备令牌。

## 6. 密码与端到端加密

### 6.1 密码派生

- 使用浏览器原生 Web Crypto。
- 密码使用 PBKDF2-HMAC-SHA-256、每空间独立 16 字节随机盐和 600,000 次迭代派生根密钥。
- 使用 HKDF-SHA-256 和不同用途标签从根密钥派生认证密钥与主密钥包装密钥，禁止同一密钥跨用途复用。
- KDF 算法、迭代数、盐和格式版本作为空间公开参数保存，方便未来平滑升级。

Worker 保存认证密钥的 SHA-256 摘要。客户端通过 HTTPS 提交派生后的认证密钥，Worker 计算摘要并做恒定时间比较；密码不离开设备。连续失败按同步空间执行递增冷却，响应不区分“空间不存在”和“密码错误”。

### 6.2 主密钥与恢复密钥

- 主密钥是随机 AES-256 密钥，不直接由密码充当。
- 主密钥使用密码包装密钥和 AES-GCM 加密后保存。
- 恢复密钥为随机 32 字节秘密，编码时带分组和校验字符，只在创建或重新生成时展示一次。
- 恢复密钥通过 HKDF 分离出恢复认证密钥和恢复包装密钥；服务端只保存恢复认证摘要和恢复包装后的主密钥。
- 使用恢复密钥重设密码会撤销全部既有设备令牌，执行恢复的设备需重新注册，其他设备需重新配对。
- 已认证设备正常修改密码时只更新密码包装与认证摘要，不强制撤销设备；用户可以选择同时撤销其他设备。

### 6.3 快照加密

- 先生成规范化快照 JSON，再计算 SHA-256 内容摘要。
- 支持时使用 gzip 压缩；不支持时保留未压缩数据并记录编码类型。
- 使用 AES-256-GCM 和每个快照独立随机 12 字节 IV 加密。
- AAD 绑定同步空间 ID、来源设备 ID、快照 ID、格式版本、工具版本、客户端创建时间和内容摘要。服务端接收时间由 Worker 单独记录并作为排序依据，客户端时间只用于快照内容说明。
- 解密、GCM 校验、内容摘要校验或格式验证任一失败时，拒绝使用该快照。
- 设备名称和用户可读备注同样使用主密钥加密；服务端只看到随机 ID、服务端时间和必要的大小、状态字段。

## 7. 快照格式与版本兼容

解密后的快照信封包含：

```json
{
  "formatVersion": 1,
  "appName": "Qin",
  "appVersion": "1.0.39",
  "schemaVersion": 1,
  "sourceDeviceId": "random-device-id",
  "clientCreatedAt": "client ISO timestamp",
  "dataHash": "sha256-base64url",
  "data": {
    "qinshi_example": "serialized-localStorage-value"
  }
}
```

规则：

- `data` 收集当前及未来所有 `qinshi_` 前缀的数据，值保持字符串，继续兼容现有备份模型。
- 下载后必须复用设置模块的统一验证逻辑，拒绝非 `qinshi_` 键、非字符串值和不支持的快照格式。
- 新版工具可以迁移旧 `schemaVersion`；迁移失败不得修改本机或云端。
- Worker 返回 `minimumReadVersion` 和 `minimumWriteVersion`。低于最低写入版本的 PWA 不允许上传或执行覆盖提交。
- 发布新增模块时按“Worker 向后兼容部署 → PWA 发布 → 公网版本验证 → 提升最低写入版本”的顺序执行，避免发布窗口中旧客户端覆盖新字段。
- 旧版本不认识的 `qinshi_` 键必须原样保留。禁止使用已过期 PWA 创建缺少新模块字段的云端最新版。

## 8. PWA 更新与同步衔接

云同步保留并复用现有 PWA 多层更新保障：

- 非缓存 `version.json` 信标。
- 首次打开、恢复前台、网络重连和定时检查。
- 失败自动重试。
- 带版本号的核心静态资源。
- Service Worker 强制回源。
- 持续更新提示和“强制修复更新”。

每次上传、下载或历史恢复前执行额外版本预检：

1. 查询 PWA 公网版本和 Worker 最低版本。
2. 若有新版，不开始读取或写入个人云数据。
3. 在 `sessionStorage` 保存待继续操作的类型与不可变快照 ID，不保存密码、主密钥或解密数据。
4. 下载并应用 PWA 更新。
5. 新版本重新载入后读取待继续操作，重新认证、重新获取元数据并自动继续。
6. 更新失败、离线或版本仍不满足要求时停止同步，本机数据不变。

因此，新增“木人”等模块时，目标设备会先获得包含该模块的工具代码，再同步包含该模块的 `qinshi_` 数据。

## 9. 设置页交互

### 9.1 未绑定状态

“跨设备数据同步”面板提供：

- 创建同步空间。
- 加入已有同步空间。
- 当前网络与 PWA 更新状态。

创建表单要求设备名称、同步密码和确认密码。创建成功后显示同步码与一次性恢复密钥，支持复制和下载凭据说明；用户确认已经保存后才能关闭。当前本机数据立即上传为该设备第一份最新快照。

加入表单要求同步码、密码和设备名称。加入只注册设备，不自动覆盖或上传本机数据。成功后进入已绑定面板，由用户明确选择下一步。

### 9.2 已绑定状态

面板显示当前设备名称、工具版本、最后上传时间、最后同步结果和云端连接状态，提供：

- 上传本机快照。
- 从其他设备同步。
- 历史与恢复。
- 设备管理。
- 安全设置。

“上传本机快照”把全部本机数据保存为当前设备最新快照。内容摘要与云端最新版相同则只提示“无变化”，不新增历史。内容不同则把旧最新版转入历史，保存新最新版，并将历史裁剪到三份。

### 9.3 选择来源设备

来源列表展示设备名称、最后上传时间、快照工具版本、快照大小和“最新/历史”标记。默认按最后上传时间倒序，不默认选中任何设备。当前设备最新版不作为跨设备来源，但可在历史恢复中选择自己的历史快照。

确认页用醒目方向显示“来源设备 → 当前设备”，明确提示当前设备全部个人数据将被覆盖。用户确认前不下载或修改个人数据。

### 9.4 设备管理与安全设置

- 重命名设备。
- 撤销设备访问。
- 撤销时选择保留或删除该设备的最新及历史快照。
- 修改同步密码。
- 重新生成恢复密钥；旧恢复密钥立即失效。
- 忘记本设备；只清除本机同步凭据。
- 永久删除整个同步空间；必须再次输入密码或恢复密钥并进行二次不可逆确认。

## 10. 覆盖同步协议

一次“来源设备覆盖当前设备”按以下顺序执行：

1. 获取来源快照不可变 ID，而不是只记“最新”别名。
2. 完成 PWA 与 Worker 版本预检。
3. 下载来源快照全部分块，校验块摘要，解密并验证快照格式。
4. 收集当前设备全部 `qinshi_` 数据，生成覆盖前 JSON 备份并触发下载。
5. 同时在 IndexedDB 保存一份临时本机回滚副本，避免移动端浏览器阻止下载时失去恢复能力。
6. 将“覆盖前本机快照”和“覆盖后当前设备新快照”加密并上传到临时区。
7. 原子替换本机全部托管数据；写入失败立即恢复旧值。
8. 提交云端事务：覆盖前本机数据成为当前设备最新一条历史，旧云端最新版按时间排在其后，来源数据的重新加密副本成为当前设备最新版，历史裁剪到三份。
9. 云端提交失败时把本机回滚到覆盖前状态，并保留临时回滚副本。
10. 云端与本机都成功后删除临时回滚副本，记录操作结果并重新载入工具。

来源快照不可变，因此操作过程中来源设备再次上传不会改变本次用户已经确认的内容。

## 11. 云端数据模型

建议 D1 表：

- `sync_spaces`：空间 ID、KDF 参数、认证摘要、密码包装主密钥、恢复认证摘要、恢复包装主密钥、最低版本、创建及更新时间。
- `devices`：空间 ID、设备 ID、令牌摘要、加密名称、撤销状态、最后使用及上传时间。
- `snapshots`：快照 ID、空间 ID、设备 ID、类型、序号、工具及格式版本、密文大小、块数、密文摘要、状态、创建时间。
- `snapshot_chunks`：快照 ID、块序号和密文 BLOB。
- `upload_sessions`：上传操作 ID、设备、预期块数与摘要、幂等键、过期时间和状态。
- `auth_throttles`：不可逆空间标识、失败次数与冷却截止时间；不保存原始 IP。

快照密文按不超过 512 KiB 分块，低于 D1 单行 2MB 限制。单份解密前快照最多 10MB；单同步空间总密文上限 100MB。达到上限时拒绝新上传并提示清理已撤销设备快照，不静默删减最新快照。

上传分为“创建会话、上传分块、完成校验、最终提交”。未完成会话不出现在设备或历史列表中；超过 24 小时的临时会话在后续合法请求中顺带清理，不依赖付费后台任务。

最终快照切换、历史排序与裁剪通过 D1 `batch()` 事务完成。任一语句失败则整批回滚。

## 12. Worker API 边界

API 使用 `/v1` 版本前缀，至少包含：

- `POST /v1/spaces`：创建空间与首台设备。
- `GET /v1/spaces/{code}/parameters`：读取公开 KDF 参数。
- `POST /v1/spaces/{code}/pair`：密码证明并注册新设备。
- `POST /v1/spaces/{code}/recover`：恢复密钥证明与密码重设。
- `GET /v1/devices`：读取设备及快照元数据。
- `PATCH /v1/devices/{deviceId}`：重命名设备。
- `DELETE /v1/devices/{deviceId}`：撤销设备并按选择处理快照。
- `POST /v1/uploads`：创建幂等上传会话。
- `PUT /v1/uploads/{uploadId}/chunks/{index}`：上传单个分块。
- `POST /v1/uploads/{uploadId}/commit`：校验并提交上传或覆盖事务。
- `GET /v1/snapshots/{snapshotId}`：读取不可变快照元数据。
- `GET /v1/snapshots/{snapshotId}/chunks/{index}`：读取分块。
- `POST /v1/security/password`：修改密码包装与认证摘要。
- `POST /v1/security/recovery-key`：轮换恢复密钥。
- `DELETE /v1/spaces/current`：永久删除同步空间。

配对接口要求密码派生认证值，恢复接口要求恢复认证值，其余接口要求有效设备令牌。所有写接口要求幂等键、工具版本、请求大小校验和严格 JSON 字段白名单。

## 13. 免费额度与费用保护

- 仅创建 Workers Free 项目和 D1 Free 数据库。
- 不启用 Workers Paid、Durable Objects、R2 付费能力或自动超额计费。
- 手动同步请求量远低于 Workers 每日免费请求额度和 D1 每日读写额度。
- 达到 Cloudflare 免费额度时 API 返回明确错误；本机继续工作，次日额度重置后可重试。
- 设置页不提供任何升级付费入口。
- 同步协议不依赖 Cloudflare 专有明文数据格式；加密快照可导出，以便未来免费政策改变时迁移。
- 现有 JSON 导入导出永久保留为平台无关的最终灾备。

第三方平台未来政策无法由项目保证。项目能够保证的是：不自动升级付费、不产生应用内费用；免费服务不可用时停止云同步而不是收费或破坏本机数据。

## 14. 异常处理

- 离线：禁用云端写操作，显示本机数据安全和稍后重试说明。
- 请求超时：有限次数重试；同一幂等键不会重复提交。
- 密码错误：不暴露空间是否存在，进入递增冷却。
- 设备已撤销：清除本机云凭据，保留本机进度和导出能力。
- 来源快照被删除：停止操作，要求重新选择，不退回到另一个快照。
- 分块缺失或摘要不符：拒绝解密和覆盖。
- 解密或格式验证失败：拒绝覆盖并报告可操作错误。
- 本地存储空间不足：回滚本机，不提交云端替换。
- 云端事务失败：回滚本机并保留 IndexedDB 临时副本。
- PWA 更新失败：不进入数据同步阶段，可使用现有“强制修复更新”。
- 页面在同步中关闭：未提交上传保持不可见；重新打开后可安全重试。已提交操作依据幂等结果恢复完成状态。

## 15. 响应式与可访问性

- 桌面端使用设备表格或宽卡片；手机和平板使用单列设备卡片。
- 所有主要按钮最小触控尺寸 44×44px。
- 不依赖横向滚动展示设备、历史、错误或确认信息。
- 破坏性操作使用独立危险色和二次确认。
- 同步进度通过文字、进度条和 `aria-live` 同时表达，不只依赖颜色。
- 同步期间锁定重复写操作；尚未进入本地覆盖前允许取消。
- 密码和恢复密钥支持显示/隐藏、复制反馈及移动端密码管理器。
- 来源与目标使用完整设备名和方向箭头，不使用含糊的“同步到最新”。

## 16. 代码组织

- `js/settings.js`：抽出并导出现有数据收集、快照生成、校验、备份下载、原子替换和回滚能力。
- `js/cloud-sync-crypto.js`：纯客户端密钥派生、包装、加解密、摘要、压缩与编码。
- `js/cloud-sync.js`：绑定状态、设备快照、上传会话、下载覆盖、历史恢复、设备管理和 PWA 更新续传。
- `index.html` 与 `css/style.css`：设置页同步面板及三端响应式界面。
- `cloud-sync/worker/src/`：路由、认证、校验、D1 仓储和错误响应。
- `cloud-sync/worker/migrations/`：只增不删的 D1 迁移。
- `cloud-sync/worker/wrangler.toml.example`：不含账号或数据库 ID 的示例配置。
- 本地 Cloudflare 凭据和实际数据库 ID 写入 Git 忽略文件，不提交 GitHub。

业务代码只保存 Worker 公共 API 地址。密码、恢复密钥、设备令牌、Cloudflare API Token 和数据库管理凭据不得写入仓库、日志或构建产物。

## 17. 部署顺序

1. 在用户自己的 Cloudflare 免费账号创建 Worker 和 D1 数据库。
2. 应用数据库迁移并部署 Worker。
3. 使用本地测试地址验证创建、配对、上传、覆盖、撤销和恢复。
4. 配置正式 GitHub Pages Origin 白名单。
5. 在 PWA 中配置 Worker 公共 URL，发布新的 PWA 版本。
6. 验证公网 PWA 版本、Worker 健康状态和完整跨设备流程。
7. 最后按需提升 Worker 最低写入版本。

创建和部署 Cloudflare 资源属于外部账号操作，实施时必须由用户明确授权登录和部署。任何账号令牌只用于当次部署环境，不写入项目。

## 19. 验收标准

- 用户能以同步码和密码在多台设备间完成配对，首次之后无需重复输入密码。
- 任意设备可上传自己的完整快照；任意其他设备可明确选择该设备并全量覆盖本机。
- 同步结果不包含任何跨设备自动合并。
- 覆盖前数据同时获得可下载 JSON 备份和当前设备最新历史快照。
- 每台设备始终最多保留一个最新快照与三个历史快照。
- 新工具模块的数据不会被旧 PWA 上传覆盖。
- 云端和传输过程中不存在个人数据、密码、恢复密钥或设备令牌明文。
- 任一故障点均不会留下半份本地数据或替换掉最后一份有效云端快照。
- 设备撤销、密码修改、恢复密钥重设和空间永久删除均可完成。
- 功能在 Cloudflare 免费额度内运行，超限只暂停同步，不产生费用。
- 手机、平板和桌面均可无横向滚动地完成全部同步操作。

## 20. 已确认的产品决策

- 手动进入设置页同步，不做后台自动同步。
- 同步码加自设密码，无需注册账号。
- 只供用户本人的多台设备使用。
- 采用设备快照模式，不采用云端最新快照自动判断方向。
- 每次从一个明确来源设备全量覆盖当前设备。
- 不自动合并任何模块或记录。
- 每台设备保留最新快照和最近三份历史。
- 覆盖前本机数据成为当前设备最新一条历史。
- 使用端到端加密。
- 记住已配对设备凭据，并提供忘记与撤销设备。
- 创建时生成一次性恢复密钥。
- 覆盖前显示来源、目标、时间和摘要并要求确认。
- 同步前先更新工具，更新后继续原同步动作。
- 同步全部当前及未来 `qinshi_` 数据。
- 仅使用免费方案，不启用任何付费项目。
