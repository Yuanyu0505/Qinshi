# 全工具性能、换行与横向滚动检查

## 范围与结论

覆盖图鉴、橙装锻造、关卡掉落、装备属性、禁地、铭文、机关兽、兵法、战匣丹囊、合阵、楼兰棋阵、答题、设置十三个模块。检查默认页、常用子页、宽泛与精确搜索、空结果、筛选、装备对比、进阶详情、个人进度编辑和计算。

视口宽度为 320、360、390、768、900、1024、1100、1200、1440 像素。补充了 30 名合成弟子的长列表，以及六种兵法资料、十九组合阵选项。所有浏览器使用隔离存储，未读取或修改用户真实个人进度。

以下是本次实测覆盖范围内的完整问题分类，不代表穷尽所有数据组合或真实设备。浏览器为桌面 Edge；390 像素性能压力场景采用四倍处理器降速，不等同真实手机测试。

**性能问题已按确认范围修改。下面所有换行与横向滚动问题均未修改，等待用户决定。**

## 一、性能问题与本轮处理

| 区域 | 发现 | 本轮处理 |
| --- | --- | --- |
| 机关兽单只计算 | 从零开始生成必然无法达标的投入方案 | 采用保守的最低投入数、最低缺口及中间状态上下界剪枝，跳过空库存状态 |
| 机关兽流派计算 | 重复计算多个机关兽的各等级候选，放大上述开销 | 复用候选缓存，缺口变小时正确重建；原优先级和材料规则不变 |
| 装备搜索与筛选 | 同时生成桌面表格和手机卡片 | 只生成当前尺寸需要的结果；越过 1024 像素断点时刷新，保留查询条件 |
| 图鉴、装备、锻造查询、锻造个人进度、禁地搜索 | 每次输入均立即重建结果 | 连续输入合并，支持中文组词；筛选、清除等明确操作仍立即执行并取消旧任务 |
| 图鉴库存编辑 | 打开、取消、切换拥有状态会重建全部卡片 | 打开和取消只更新目标卡片；拥有状态只更新同行备注框，保存时仍按规则重新查询 |
| 战匣丹囊编辑 | 改等级、装备或品质会重建整片进度列表 | 保留编辑输入与其他弟子节点，只刷新等级上限、品质和槽位状态 |
| 兵法库存和价格 | 合法填写后重建完整计算表单 | 尚未计算时局部更新；已有结果或之前存在输入错误时保留完整刷新，防止显示与计算值不一致 |
| 图鉴、手机装备、禁地长列表 | 屏幕外卡片也参与初始布局绘制 | 保留所有结果节点，远处卡片延迟绘制，进入视口后恢复 |
| 铭文 | 已有防抖、子页面缓存、屏幕外绘制；首次宽泛查询仍有成本 | 保留既有优化，不重构数据与交互；未发现需要重复重做的同类更新逻辑 |
| 其余区域 | 所测切换和输入未复现与机关兽相当的持续阻塞 | 保持现状，未做无依据改动 |

### 代表测量

- 破土七郎：当前研发度 1000、目标 10 级，旧版桌面约 2.5～3.5 秒；新版约 3～5 毫秒。仍为投入 273、研发 316740、溢出 40、蓝图 816、机关 3270。
- 霸道流派默认一阶计算：旧版桌面约 36～47 秒；新版约 0.12 秒。降速场景新版仍约 0.7～1 秒，并非所有复杂计算都已“零等待”。
- 同轮桌面宽泛搜索，输入事件及同步布局：装备约 51 毫秒→不足 1 毫秒，图鉴约 49 毫秒→不足 1 毫秒，禁地约 55 毫秒→约 1 毫秒。
- 连续三个输入事件现在只产生一次结果重绘，原为三次。

注意：上面的搜索耗时是**输入处理阻塞**，不是全部结果出现时间。为了连续打字不卡顿，最终结果在停止输入约 120 毫秒后统一刷新，再加实际渲染时间。因此单次短查询不保证更早出结果；低速设备首次大列表仍会有短暂开销。不能把这一改动描述为所有查询“瞬间完成”。

### 验证

- 核心与本地服务回归测试通过 244 项。
- 新增浏览器行为测试通过 11 项，覆盖：输入合并、尺寸切换、图鉴库存局部更新、战匣等级保存、兵法输入校验、远处卡片滚动恢复、快速筛选与锻造返回。
- 83 组新旧机关兽算法对照结果完全一致，覆盖 27 种机关兽、有无库存、改造、高阶等价权重及两组多目标缓存调用。
- 独立只读审查发现的兵法错误输入残留问题已补测试并修复。

## 五、建议用户决定的顺序

1. 先判断是否处理 H11、H12：这是整页被撑宽，不是资料表设计性横滑。
2. 再判断 W1、W7：分类名称拆字、数值范围断行会影响阅读。
3. 其余宽表 H1～H10 可按模块选择“手机卡片／按阶段分组／折叠次要信息”，不建议为塞进一行把所有文字无限缩小。
4. W13～W21 的长说明建议保留自然换行。
