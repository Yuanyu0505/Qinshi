# 橙装锻造个人进度装备搜索设计

## 1. 目标

在“橙装锻造 → 个人进度”中增加跨全部弟子的装备搜索。用户输入装备名称关键词后，系统同时回答：

1. 哪些弟子直接持有名称匹配的主装备；
2. 哪些弟子的哪些主装备，在尚未完成的锻造阶段中需要名称匹配的装备作为材料。

结果必须完整展示对应主装备的当前进度、下一阶段和全部剩余锻造明细。

## 2. 已确认的搜索规则

- 搜索范围覆盖全部弟子，不受当前分页限制。
- 使用装备名称关键词模糊匹配，去除首尾空格并忽略英文字母大小写。
- 弟子直接持有的主装备始终参与搜索，即使该装备已经全部锻造完成。
- 作为锻造材料的装备只匹配主装备当前进度之后尚未完成的阶段。
- 直接持有和材料需求分区展示，不相互去重。
- 同一主装备的多个未完成阶段均命中时，只生成一张关系卡，并在卡内保留全部命中阶段。
- 同一装备被同一弟子添加多次时，按独立装备实例分别展示。
- 清空搜索词后恢复原来的汇总页和单弟子分页，并保留搜索前页码。

例如搜索“非攻”时，可以同时展示弟子直接持有的“非攻九变”，以及另一位弟子的“雷神锤”在未完成阶段中对“非攻”的材料需求。

## 3. 实现方案

采用个人进度独立搜索方案：在 `js/progress.js` 中增加无 DOM 依赖的纯搜索逻辑，在 `js/app.js` 中维护搜索状态和渲染结果。

不复用 `js/forging.js` 的普通查询作为核心搜索逻辑。普通查询面向完整静态配方，不理解弟子归属和当前进度，强行复用会增加二次过滤和数据拼接的复杂度。

不建立额外搜索索引。锻造数据只有 156 件，个人进度规模较小，直接遍历足够简单可靠，也避免索引与进度状态不同步。

## 4. 组件职责

### `index.html`

- 在个人进度顶部工具栏下方增加全局装备搜索框。
- 增加独立搜索结果容器。
- 保留普通“查询”模式、全体汇总和单弟子分页的原有结构。

### `js/progress.js`

增加个人进度搜索纯函数，输入锻造数据、全部弟子进度和搜索关键词，输出：

- `owned`：弟子直接持有且装备名称命中的结果；
- `required`：未完成阶段的材料名称命中的结果。

每个 `owned` 结果保留弟子、个人装备实例和对应锻造数据。每个 `required` 结果保留弟子、主装备实例、对应锻造数据，以及全部命中的未完成阶段和材料位置。

该模块不读取 DOM、不访问 `localStorage`，确保搜索规则可以独立理解和复用。

### `js/app.js`

- 在个人进度状态中维护搜索关键词。
- 监听搜索输入并调用 `progress.js` 的搜索函数。
- 有有效关键词时隐藏原汇总/分页内容，显示跨弟子搜索结果。
- 清空关键词时隐藏搜索结果并恢复原页码。
- 复用现有装备进度卡片和锻造材料渲染逻辑，避免形成两套不一致的进度展示。
- 弟子进度被修改后重新渲染时，当前搜索结果同步反映最新阶段。

### `css/style.css`

- 增加个人进度搜索框、结果分区标题、数量标记和命中阶段强调样式。
- 沿用现有深色水墨主题及响应式规则。

## 5. 数据流

1. 用户进入“个人进度”，原汇总/分页界面照常工作。
2. 用户输入装备关键词，页面规范化关键词并调用个人进度搜索函数。
3. 搜索函数按弟子添加顺序遍历个人装备实例。
4. 装备实例名称命中时加入 `owned`，不受完成进度限制。
5. 搜索函数从该装备的当前进度开始遍历剩余阶段；材料名称命中时，按“弟子 + 主装备实例”聚合到 `required`，收集全部命中阶段。
6. 页面分别渲染两类结果及计数。
7. 清空搜索词后恢复原汇总/分页界面，不修改任何个人进度数据。

## 6. 展示与排序

### 弟子直接持有

每条结果展示：

- 弟子名；
- 装备分类、品质和名称；
- 已完成阶段数；
- 下一锻造阶段；
- 全部剩余阶段及材料；
- 全部完成状态。

### 尚未完成的锻造材料需求

每条结果展示：

- 弟子名；
- 需要该材料的主装备分类、品质和名称；
- 主装备当前进度；
- 命中的材料名称与品质；
- 所有命中的具体阶段；
- 主装备下一阶段及全部剩余阶段材料。

排序规则为：

1. 弟子添加顺序；
2. 同一弟子内按“武器 → 盔甲 → 首饰 → 典籍”；
3. 同类装备保持添加顺序。

## 7. 空状态与异常数据

- 空白关键词不执行搜索，显示原个人进度界面。
- 两类结果均为空时显示“未找到匹配装备”。
- 只有其中一类为空时，该分区显示对应空提示，另一分区正常展示。
- 进度中存在已从锻造数据移除的旧装备时，仍可按保存的装备名产生直接持有结果，并标注“锻造数据缺失”；该记录不产生材料需求结果。
- 缺失或异常的弟子装备记录安全跳过，不影响其他正常结果。
- 弟子名、装备名和动态文本继续进行 HTML 转义。

## 8. 数据兼容与改动边界

- 不修改 `qinshi_forging_progress_v1` 的存储格式，已有个人进度无需迁移。
- 不修改自动生成的 `data/forging.js`。
- 搜索为只读操作，不触发保存，不改变弟子、装备或锻造阶段。
- 不改变橙装锻造普通查询、其他功能分区或数据构建脚本。

## 9. 用户手动验证建议

按照本项目 `AGENTS.md`，功能验证由用户自行执行。建议重点检查：

- 模糊搜索可以找到弟子直接持有的装备；
- 已全部完成的直接持有装备仍能找到；
- 材料搜索只展示尚未完成阶段；
- 已完成阶段的材料不再出现；
- 同一主装备多个阶段命中时合并为一张卡并列出全部命中阶段；
- 同一关键词可同时产生直接持有和材料需求两类结果；
- 多弟子、多装备结果完整且顺序正确；
- 清空搜索后恢复搜索前页码；
- 修改锻造进度后，当前搜索结果随之更新；
- 桌面与手机宽度下均可完整阅读和操作。
