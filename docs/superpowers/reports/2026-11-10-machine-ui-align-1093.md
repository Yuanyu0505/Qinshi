## 图4枚举结论

使用用户新提供备份中唯一的机关兽记录，只读取机关兽进度、库存与价格；不导入真实账号，不提取其他分区资料，不提交原始备份或账号标识。

备份可确认：非攻当前累计 **97级**，3阶目标 **135级**，必须精确增加 **38级**；蓝紫仅用库存、神图库存 **0张**、单价 **70元宝/张**。按截图“仅新增0阶、不新增改造”分析；全兽参与、完整库存可用作为搜索上界。

**结论：最多新增6个效果解锁节点；在所有6节点精确达标组合中，最低已计价元宝为647,052。图4正好达到这个下界，没有更便宜的6节点组合。**

有两套同价且同正式比较指标的组合：

| 培养组合 | 新增等级 | 新增节点 | 新增实物 | 已计价元宝 |
|---|---:|---:|---:|---:|
| 机关玄武0→20、机关年兽2→20 | 20+18=38 | 3+3=6 | 18+17=35只 | 647,052 |
| 机关白虎0→20、机关年兽2→20 | 20+18=38 | 3+3=6 | 18+17=35只 | 647,052 |

两套均最终累计135级，研发度溢出合计60,000，神图合计3,360。产品稳定键最终只需选定其中一套展示；“存在其他同价方案”不等于“现方案不最优”。

### 金额拆解

- 玄武（或白虎）：18只×40碎片×600贡献÷2.7 = **160,000元宝**。
- 年兽：ceil(17只×40碎片×1,000贡献÷2.7) = **251,852元宝**。
- 神图：(18+17)×ceil(48,000÷500) = **3,360张**；×70 = **235,200元宝**。
- 合计：160,000 + 251,852 + 235,200 = **647,052元宝**。
- 最终生效是两只各自20级最高档，不是三个低档效果叠加；新增节点数另算为3+3。

### 独立枚举方法与覆盖

脚本：`tools/machine-beasts-zero-rank-audit.cjs`。没有调用产品单兽候选生成、状态去重或CORE函数来生成枚举候选。只在独立枚举完成后，调用产品流派接口作结果对照。

1. 对每只兽枚举其0改0阶材料数量，从0到库存上限（蓝紫）或最少足以达到该兽最高等级的数量（新增橙兽）。超过封顶所需的额外材料不改变等级/节点且不可能减少费用、溢出或神图，因此无需枚举无限多的冗余投入。
2. 逐数量直接计算真实最终等级、`current < effect.level <= final`节点数、逐兽碎片缺口、精确向上取整费用及神图，不使用产品候选集合。
3. 独立动态枚举组合，状态使用真实 `(新增等级,新增节点数)`；超过38级立即排除，最后只接受恰好38级。
4. 本例神图库存为0、价格为整数70，各兽费用和资源可加。对同一精确等级/节点状态，保留 `(元宝,溢出,神图)` 字典序最小项是安全的：任意后续兽选择给二者增加完全相同的独立项，不会反转排序。没有使用产品的支配/截断实现。
5. 同时累计全部原始数量向量的路径数，而非只计保留的最优项。**238个逐兽数量候选、20,648次状态转移，覆盖478,071,370个精确达标数量组合**；这是动态枚举覆盖计数，不声称逐一物理遍历4.78亿条路径。

每个确切新增节点数下的最低元宝：

| 节点数 | 最低已计价元宝 |
|---:|---:|
| 0 | 437,772 |
| 1 | 425,920 |
| 2 | 425,921 |
| 3 | 433,434 |
| 4 | 440,947 |
| 5 | 478,067 |
| 6 | 647,052 |

没有7个或更多新增节点的精确达标状态。独立枚举与原产品返回一致：投入最小425,920元宝/1节点，最多效果647,052元宝/6节点。**无需修改求解算法。**

### 结论边界

备份保存个人进度与参考价格，不保存临时计算现场的参与开关、库存使用上限、临时研发度及新增材料开关。材料开关依据截图，其余按上述范围明确建模。

若只减少参与兽、关闭库存或收紧使用上限，且原图组合仍可行，不可能得到比该全范围最低值更低的费用，因此这种限制不推翻下界。但若临时修改了其他兽的研发度、价格、碎片，或允许新增其他阶数/改造，则属于不同输入，不能套用本结论。
