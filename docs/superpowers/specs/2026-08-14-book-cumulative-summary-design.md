# 典籍累计汇总与神兵属性补齐设计

## 目标

修正装备属性分区中的神兵装备数据，并将所有“典籍 / 神兵典籍”的阶段效果统一解释为同品质内逐阶累计。默认结果只展示该品质最高阶的最终累计效果，需要查看成长过程时再按品质展开详情。

## 数据修正

### 标准名称

- `神兵月狼锦纱`
- `神兵月华袍`
- `神兵火魅耳环`

生成阶段统一使用以上名称，避免重新读取 Excel 后恢复为简称。

### 神兵破阵弓

主属性保持为“攻”，补齐：

- 橙色：`5%暴伤`、`10%抗暴`
- 橙金：`10%暴伤`、`10%抗暴`
- 红色：`10%暴伤`、`10%抗暴`
- 红金：`15%暴伤`、`10%抗暴`

### 神兵月华袍

主属性保持为“防”，补齐：

- 橙色：`6%穿透`、`6%暴伤`
- 橙金：`8%穿透`、`8%暴伤`
- 红色：`10%穿透`、`10%暴伤`
- 红金：`10%穿透`、`15%暴伤`

这些修正写入生成源逻辑并重新生成 `data/special-equipment.js`，不直接把生成文件作为唯一修复点。

## 典籍累计规则

累计仅发生在同一本典籍、同一个品质内部，不跨品质累计。

- 0阶累计效果：0阶原始词条。
- 5阶累计效果：0阶 + 5阶原始词条。
- 10阶累计效果：0阶 + 5阶 + 10阶原始词条。
- 15阶累计效果：0阶 + 5阶 + 10阶 + 15阶原始词条。

相同属性数值相加；不同属性全部保留。`攻防血`保持为一个复合词条，累计后仍同时满足“攻 / 防 / 血 / 攻防血”副属性筛选。速度与敌方减攻、敌方减防、敌方减血等其他数值词条使用相同累计规则。

原始 `stages` 数据保持不变，累计结果由查询核心的纯函数计算，防止重复累计，也保留原始成长数据。

## 默认展示

每个品质单元格默认只展示最高阶累计效果：

- 紫色、橙色：显示`10阶累计`及其最终累计属性。
- 橙金、红色、红金：显示`15阶累计`及其最终累计属性。
- 神兵典籍没有紫色档，按实际存在的品质展示。

默认不再同时铺开0阶、5阶、10阶、15阶多行数据。

每个品质单元格提供独立的“详情”按钮：

- 初始为收起状态。
- 点击“详情”后，展开当前品质的阶段成长明细。
- 紫色、橙色展开0/5/10阶；其他品质展开0/5/10/15阶。
- 详情中的每一阶都显示截至该阶的累计效果，而不是只显示该阶新增词条。
- 展开后按钮文案变为“收起”，再次点击恢复默认最高阶摘要。

桌面表格和移动端卡片共用同一累计结果及展开语义，不更改非典籍装备布局。

## 筛选与排序

- 副属性筛选仍检查整本典籍在各品质、各阶段拥有的属性；复合词条匹配规则不变。
- 选择具体品质排序时，使用该品质最高阶累计值：紫色、橙色取10阶，橙金、红色、红金取15阶。
- “最高值”排序比较各品质最高阶累计值，选择其中最大的累计结果。
- 排序值标签显示累计后的真实值，例如神兵鬼谷子红金应显示`41%暴击`或`35%抗暴`。
- 非典籍装备继续使用原有单档副属性排序逻辑，不受累计规则影响。

## 代码边界

- `tools/build_special_equipment.py`：标准名称和两件神兵装备属性修正的生成源。
- `data/special-equipment.js`：由生成脚本重新产生的当前数据。
- `js/query.js`：典籍阶段累计、最高阶累计、累计排序token；非典籍逻辑保持兼容。
- `js/app.js`：默认最高阶摘要，以及按品质展开/收起成长详情。
- `css/style.css`：摘要与详情按钮的分区内样式。
- `tests/test_build_special_equipment.py`、`js/query.test.js`、`serve.test.js`：数据、累计、排序与渲染契约。
