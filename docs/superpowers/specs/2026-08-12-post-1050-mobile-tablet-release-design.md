# 10:50 后工具更新的手机、平板适配与发布设计

## 目标

将 2026 年 8 月 12 日 10:50（北京时间）之后截至当前的全部工具改动适配到手机和平板，并在适配完成后推送 GitHub `main`，由现有 GitHub Pages 工作流发布最新版 PWA。

## 一、更新基线与功能范围

本次以本地 `master` 当前最新内容为准，覆盖 10:50 后全部 17 个提交所包含的功能，而非只适配最后一次界面修改。范围包括：

- 典籍与神兵典籍装备属性、分类、主副属性和档次显示。
- 全工具“技伤减免/技免”名称统一后的显示。
- 装备属性待筛选状态、装备名称品质样式和典籍排版。
- 图鉴升级汇总所需装备默认折叠。
- 橙装锻造查询区顺序、个人进度弟子搜索和空查询间距。
- 典籍各档次的阶段及属性对齐。
- 动态分区标题和 `Qin` 安装名称。

不修改这些功能的业务数据、筛选规则或本地存储结构，只补齐跨端展示和交互。

## 二、目标设备和布局策略

同时适配：

- 手机竖屏。
- 手机横屏。
- 平板竖屏。
- 平板横屏。

采用现有响应式结构增量补齐：

- 手机以单列、卡片、自动换行为主，避免整个页面横向滚动。
- 平板保留信息密度较高的表格；只有表格容器内部允许横向滚动。
- 桌面布局保持现状，不因移动适配发生结构性变化。
- 手机底部导航继续固定；横屏压缩导航和页面底部留白，避免遮挡内容。
- 平板继续使用左侧导航和右侧内容区，横竖屏均保持合理留白。

## 三、全局标题与导航

- 页面顶部和浏览器标签继续只显示当前分区名。
- 初始分区显示“图鉴”，切换八个分区时同步更新。
- PWA 安装名称继续使用 `Qin`。
- 手机底部导航及“更多”弹层继续共用当前分区切换逻辑。
- 不恢复已移除的内容区重复标题、数量和版本信息。

## 四、装备属性分区

### 4.1 全端默认状态

- 手机、平板和桌面每次进入装备属性分区时均清空筛选并隐藏结果。
- 输入关键词或主动点击筛选条件后才展示结果。

### 4.2 手机普通装备

- 普通装备继续使用现有卡片结构。
- 装备名称保留品质高亮：紫色装备紫底、紫框、白字；橙色装备橙底、橙框、白字。
- 主属性、副属性和排序值允许换行，不超出屏幕。

### 4.3 手机典籍与神兵典籍

- 每件典籍使用一张卡片，展示分类、装备名称和主属性。
- 紫色、橙色、橙金、红色、红金分别作为可展开档次；只输出该装备实际存在的档次。
- 默认展开当前选择的取值档位。
- 取值档位为“最高值”或尚未指定时，默认展开该装备实际存在的最高档，通常为红金。
- 点击档次标题可展开或收起；同一卡片允许展开多个档次。
- 每个档次内部使用固定的“阶次列 + 属性列”：阶次右对齐，属性左对齐。
- 属性词条纵向排列，不恢复“+”连接符。
- 单阶段紫色或橙色档只展示实际 `10阶` 数据，不生成不存在的阶段。

### 4.4 平板典籍表格

- 平板继续显示完整表格，不切换为手机折叠卡片。
- 阶次标签、属性起点和多档次阶段分隔线保持统一对齐。
- 表格容器内允许横向滚动，页面本身不横向溢出。
- 分类、装备名和主属性区域在滚动时保持可辨认，不允许滚动内容穿透或叠在关键列下方。

## 五、图鉴分区

- 手机和平板顶部“当前结果升至 X 级汇总”中的所需装备默认折叠。
- 点击展开后，装备标签在容器内自动换行，不撑宽页面。
- 页签、搜索、等级范围或目标等级变化后恢复默认折叠。
- 单个图鉴项目及其搜索筛选在手机横竖屏、平板横竖屏下使用可用宽度，不产生整页横向滚动。

## 六、橙装锻造分区

- 查询面板保持位于“锻造材料总览（四大类通用）”上方。
- 搜索为空时继续隐藏结果容器，不恢复占位空白。
- 手机个人进度的阶段和材料保持两列布局，列宽使用可用空间，材料标签允许换行。
- 弟子搜索结果、直接持有装备和未完成材料需求在窄屏下纵向排列；姓名、装备和阶段标签可完整换行。
- 手机单个弟子剩余材料汇总保持两列。
- 平板材料总览和“作为素材装备”结果继续在局部容器中滚动，并正确固定关键首列；滚动内容不得从固定列左侧露出。
- “作为主锻造装备”结果不强制冻结首列。
- 新增典籍名称及“技免”等文字必须完整显示。

## 七、铭文、答题和其他分区

- 铭文个人进度和查询继续沿用手机单列、平板高密度布局。
- 铭文资料图表在平板及手机的表格容器中保留关键首列，并避免滚动穿透。
- “技免”及其他今天新增或统一的词条允许完整换行。
- 答题、楼兰棋阵、关卡掉落和设置保持现有业务逻辑，只补齐横竖屏宽度、间距和长文本换行。

## 八、数据兼容与文件保护

- 保留所有 `qinshi_` 本地存储键和既有数据格式。
- 不修改或迁移个人锻造进度、图鉴等级、铭文记录、答题数据和设置备份结构。
- 不暂存或推送主工作区未跟踪的 `答题.jpg`。
- 不覆盖用户当前修改的 Excel 工作簿。
- 不删除现有保险 stash。

## 九、版本与发布

- 适配完成后同时提升 `js/pwa.js` 中的显示版本和 `service-worker.js` 中的缓存版本，确保已安装设备收到新资源。
- 将完成适配的本地 `master` 推送至 `origin/main`。
- 现有 `.github/workflows/pages.yml` 在 `main` 推送后构建并部署静态站点。
- 不创建额外部署分支，不改变 GitHub Pages 工作流结构。
- 发布完成后提供 Pages 地址和手机、平板更新步骤：联网打开一次，按更新提示刷新；如仍为旧缓存，从设置页检查更新或重新打开 PWA。

## 十、建议用户手动验证

- 四种屏幕场景下依次检查八个分区的顶部标题和导航。
- 检查装备属性进入时无默认结果，普通装备卡片和典籍折叠卡片均正常。
- 检查平板典籍表格的阶段、属性、分隔线和滚动遮挡。
- 检查图鉴汇总装备默认折叠及展开换行。
- 检查锻造查询、个人进度、弟子搜索、两列材料以及平板表格固定列。
- 检查铭文资料表、长词条和“技免”显示。
- 检查 PWA 名称为 `Qin`，既有本地进度仍可读取。
- 检查 GitHub Pages 已加载最新版本。
