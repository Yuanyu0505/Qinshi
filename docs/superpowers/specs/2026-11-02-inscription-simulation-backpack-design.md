# 铭文模拟背包与配方可读性

用户已确认整体方案及八项选择，文档和计划无需再次确认。

## 目标与边界
- 所有路线去掉“下一步”内框，放大准备/总数/批次数量；按配方就近摆放晋升材料、独立汇合与分叉，避免不同批次共线造成误读。
- 虚拟背包按游戏账号长期保存、随既有账号数据备份和同步，不接触真实铭文进度。
- 手填只代表洗练；紫色开始不能手填中档，已有模拟合成品从背包取用。旧现场保留，明确确认来源后继续。
- 加入背包幂等；next自动入包并预选。roll扣材料，retry撤销本次结果并用原材料重抽，允许相同结果并显示次数。repeat保留产物和配方，背包不够不自动复制。back逐步撤销。
- 数量手增为独立手动补充批次；数量减少/移除/清空先确认，不能静默覆盖被占用材料。对手动背包变更后的撤销检测冲突。
- 最终产物可追溯实际使用的合成链；手动材料是叶子，不虚构制作步骤，不加入废弃重抽或未用结果。

## Approaches
采用统一模拟事务模块：批次库存、不可变来源记录、可逆库存差额与模拟现场。拒绝仅在UI添加按钮（无法保持账目/撤销/路线一致）和复用旧按目标库存（不能按账号共用）。

## 数据与界面
沿用qinshi_inscription_crafting_v1账号存储，在simpleWorkbench中扩展lab字段；保留旧存档其他字段。存储层继续使用现有账号/并发token检测。
独立模块inscription-simulation.js消费Rules，提供upgrade/validate/preview/act/route纯函数。页面只负责显示与一次保存。每个产物记录投料来源、概率和晋升材料；库存批次引用来源记录。撤销不回滚无关用户编辑。
背包使用可折叠面板，数量、来源、选择与错误提示支持窄屏；完整实际路线复用现有SVG渲染器和缩放。
