## 0. 任务与绝对边界

基于 Qin 项目**当前工作区实际源码**增加一级模块「其他资料」，内部包含九个固定分区：
1. 诸子卡；2. 五行天枢录；3. 橙弟子来源；4. 灵宝；5. 极限速度；6. 守护神；7. 功能开放等级；8. 器灵；9. 弟子相关。

必须直接实施源码、测试并交付结果，而不是只给构想。新模块定位为**只读资料查询库**，以已有图片的原始资料为唯一事实依据。优先为可读性提供搜索、局部筛选、按需展开、对照表和原图查看；除非用户后续明确要求，**不新增模拟器、数值计算器或推荐算法**。

严格禁止改变：现有所有计算公式、数据表、游戏资料、现有搜索/筛选语义、账号/角色权限、原有存储键和格式、库存、备份恢复、跨模块业务导航含义、其他功能页面。只读「其他资料」默认无需账号权限和持久化业务状态。不要借新增资料顺便“修正”原有模块中的数据。

## 4. UI / UX 规范（要达到“可读性拉满”）

- 一级模块进入后，**默认打开九分区索引**，每项一行说明它可以查什么；可点击转子分区。移动端不把九个大按钮堆成过长首屏，采用3×3紧凑入口或可横向滚动的分区导航，实际以可用内容宽度为准。
- 每个分区保留“所属分区/子栏目/来源图”的层级路径，并有返回九分区的明显入口。查完一张表不能丢失刚才所在分区位置。
- 高频资料（五行气蕴、功能等级、橙弟子来源）默认直接可读；长技能和长攻略适当折叠。**不为每行表格加一个需要点击的详情按钮**，要减少重复操作。
- 以文字标签、单位和清晰数字展示差异；颜色辅助但不能唯一承载语义。背景采用现有黑金风格，表格维持清晰对比，不照搬外部攻略图的花哨底色与水印。
- 数值和单位分列或清晰相邻，不把百分数、万、个等混在同一个未经标注的数字字段；原图未提供数值时显示“未提供”，而不是0。
- 源图预览：原图可完整查看、放大、平移，支持手机手势与键盘关闭；**不上传用户图到外部服务**。高分辨率图片延迟加载，避免九个分区一进入就下载所有大图。
- 长表：局部水平滚动+滚动提示；首列（名称/等级）可固定，但需避免移动端固定列占据大部分宽度。宽表桌面行高适当，手机可切换卡片视图。
- 只读筛选和排序只影响当前「其他资料」分区；不修改现有模块中任何筛选状态、URL片段含义或排序逻辑。
- 空搜索、加载失败、来源待核对分别给出不同状态。文本保留可复制能力。
- 不用水平滚动隐藏九分区其中若干导航而完全无提示；避免低对比度辅助字。
- 响应式实测：320×568、375×667、390×844、430×932、768×1024、820×1180、1024×768、1280×720、1366×768、1440×900、1920×1080，及125%/150%/200%缩放。
- 优先复用项目既有组件、事件委托与 CSS 变量；不用新大框架、不大量堆叠后置CSS覆盖补丁。不设置覆盖其它模块的全局 CSS。

## 6. 数据录入与严格校对流程

1. 将本包全部原图放入项目静态资源目录，保持原图可追溯；建立源文件→分区→子栏目的映射。
2. 优先结构化已清晰的五行气蕴CSV与红卡分段；对高密度表格采用放大/局部裁切**人工比对**，不要只凭全图缩略图判断，也不要把OCR当成最终事实。
3. 每行、每列保留原图名称、数字、符号、负号、小数和单位；区分“本级消耗”“累计合计”“原图举例”。
4. 自动检查可核实的恒等式（如新五行气蕴表每个气蕴五行和=1500，五极石初/中5×270=1350、高级5×810=4050），但发现不一致应记录，不擅自修正原文。
5. 所有大型表至少随机抽查20%，关键技能百分比、速度排名、材料总计须逐项核对。
6. 对图08/09/10/11/12/13/15/17及对应补图，必须先逐页检查再录入；未完成核对时先上线清晰原图模式也可，但**不得标注“已完整结构化”**。如用户要求一次性完整交付，不能凭猜测补齐。
7. 红卡传说卡册防御合计已经由用户确认：**三册12w防**，不是原图的6w。详见 `04_实施与验收/待核对来源差异.md`；结构化展示采用12w，原图保持原样，不再显示“待核对”提示。
8. 结构化完后生成 `DATA_AUDIT.md`：分区条目数量、结构化数量、图片覆盖率、疑点及来源索引。不得用“有图片”等同于“文字已完全核验”。

## 7. 迭代实施顺序

- **阶段A：只读框架**：九分区入口、索引导航、响应式容器、原图查看、无业务存储、无现有模块回归。
